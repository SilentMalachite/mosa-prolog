# マニュアルの例と `mosatest --manual`

このディレクトリには `mosatest --manual` の見本（`good`、`bad-output`、`bad-ids`、`unmarked`、`empty`、
`bad-preds`、`bad-lib`。`tests/tests.cmake` で登録する）を置く。下の規則は `docs/manual/` の章を書く人のためのもの。

```text
mosatest --manual <dir> [--mosa <path>] [--work <dir>] [--all-tables]
```

`<dir>` は `en/` と `ja/` を持つ。`--mosa` の既定は動いている `mosatest` の隣の `mosa` で、例の中の `mosac` と
`mosatest` はその `mosa` の隣のもの。`--work` の既定は `tests/tmp/manual`。検査器は失敗ごとに 1 塊（`file:line id`、
期待した出力、実際の出力）を出し、最後に `manual: N checked, M skipped, F failed` を出す。この最後の 1 行は文面の
言語によらず同じ字なので、スクリプトはどちらの言語でも同じ形で読める。N と M は例を数える。F は失敗した例と、構造の
誤り（読み取りの誤り、片方の版に無いファイル、違う id か述語の表、Mosa と違う述語の表、空にできない章のディレクトリ）を
すべて数える。終了コードは、失敗が無ければ 0、失敗があれば 1、使い方の誤りは 2。`<dir>` に読める `en/` か `ja/`
が無いとき、`check:` の例が 1 つも無いとき（何も確かめていないので、通ったことにしない）、`<--mosa> --version` が
動いている `mosatest` の版の 1 行を出さないとき、`--mosa` の隣の `lib/` を読めないときも 2。

## 印

`en/*.md` と `ja/*.md` のコードブロックは、`README.md` の中のものを除き、開きの囲いの直前の行に次のどれかを持つ。
印の無いコードブロックは誤りで、コードブロックの直前に無い印も誤り。

| 印 | 意味 |
| --- | --- |
| `<!-- check: ID -->` | 動かして出力を比べる。 |
| `<!-- skip: ID -->` | 動かさない（インストール、OS ごとの手順、検査器が動かせないもの）。 |
| `<!-- file: ID NAME -->` | `prolog` のコードブロックを、章のディレクトリに `NAME`（ディレクトリを含まないファイル名）として書く。 |

`ID` は空白を含まず、1 つのファイルで 1 度だけ使う。章の両版は同じファイル名を持ち、印の種類と id の並び（印の
3 種すべてを数える）も同じにする。こうして `en` と `ja` は同じ例を同じ順に見せ、片方の版だけが `check:` の例を
`skip:` にすることもできない。

囲いの行は開きも閉じも 0 桁目に置く。空白 1 つ以上で字下げした囲いの行は箇条書きの項目の中でも誤りで、ブロック
引用（`>`）の中、箇条書きの印（`- `、`1. `）と同じ行、タブの後ろの囲いも誤り。GitHub はそうした行を文、字下げの
コード、箇条書きの一部のどれとしても読みうるから。番号付きの手順の間に例を置くときは、箇条書きをそこで終え、印と
囲いを 0 桁目に置き、次の番号（`3.`）で続ける。GitHub は番号付きの箇条書きの始めの番号を保つ。囲いの無い字下げの
コードブロック（空白 4 つ）はまったく読まず、印も要らないので、例には使わない。

複数行の注釈を閉じる行の印は誤り。GitHub はその印を注釈の中に隠すから。その行で閉じない書き違えた印の注釈を
閉じる行も同じ。

## `check:` が動かすもの

- 1 行目が `?- ` で始まる `text` のコードブロックは、引数なしの `mosa` を動かす。端末の前の読者と同じ。
- `console` のコードブロックはコマンドの並び。`$ ` で始まる行がコマンドで、期待する出力は次の `$ ` の行までの行
  （空の行も含む）。コマンドは `mosa`、`mosac`、`mosatest` か `./NAME`（章のディレクトリのプログラム。Windows では
  `.exe` を足す）で始める。引数は空白で分け、`'…'` と `"…"` はシェルと同じく語をまとめる。POSIX のシェルが特別に
  扱う字は誤りにするので、コマンドはシェルが渡すのと同じ引数で動く。引用の外では ``\ $ ` | & ; < > ( ) * ? [ # ~``、
  `"…"` の中では ``\ $ ` `` が誤り。`'…'` の中はすべて字のまま。コマンドは順に動き、最初に違ったところでその
  コードブロックを止める。
- ほかのコードブロックの `check:` は誤り。

## 入力

既定の入力は、期待する出力のうち `?- ` で始まる行の `?- ` の後ろを、1 行ずつ改行を付けて並べたもの。それ以外
（次の答えを求める `;`、`read/1` が読む入力、複数行の問い合わせ）は印の中に書く。

```text
<!-- check: ID
(X = 1 ; X = 2).
;
-->
```

`<!-- check: ID` と `-->` の間の行が、空の行も含めてそのまま入力になる。`console` のコードブロックでは、どのコマンドも
この入力を受ける。入力のどの行にも `-->` は書けない（DCG の規則など）。GitHub はそこで注釈を閉じ、入力の残りを
文として映すから。そうした入力は `file:` のブロックに書いて読み込む。

## 出力の比べ方

どの実行も `LANG=en_US.UTF-8`（`en`）か `LANG=ja_JP.UTF-8`（`ja`）と `MOSA_TRANSCRIPT=1` を受け、`MOSA_LIB`、
`MOSA_HEAP_MAX`、`MOSA_GC_STRESS` は消す。`MOSA_TRANSCRIPT=1` の `mosa` は入力の行を書き返すので、出力は端末に
映るものと同じになる。標準出力と標準エラーは 1 つにまとめる。1 バイトずつ比べる前に、両側の `\r` を除く。入力が
あり、その最後の行が `halt.` でないときは、その入力の終わりで `mosa` が待っている最後の `?- ` も除く。それ以外で
最後に残る `?- ` は除かない。読者の画面でもその促しが出たまま待つからである（`-t halt` の無い `mosa -g G` を入力
なしで動かすときなど）。

終了コードは比べない。エラーを見せる例は 0 以外で終わるのが正しいことがあるからである。ただし落ちた実行は、期待
する出力が空でも失敗にする。POSIX ではシグナル（シェルと同じく 128 より大きい終了コード）、Windows では `NTSTATUS`
のエラー（0xC0000000 以上）、それと出力のファイルが無いとき。`;` の返事の後に `mosa` は空の行を出すので、期待する
出力にもそれを書く。実行に時間の上限は無いので、止まらない例は検査全体を止める。

## ファイル

`file:` のコードブロックは、検査器がそこまで来たときに `<work>/<版>/<章の語幹>/NAME` に書かれ、その章のどの例も
そのディレクトリを作業ディレクトリとして動く。そのディレクトリは章の初めに空にするので、ほかの章や前の回の
ファイルには頼れない。空にできないときは、その章を動かさずに失敗に数える。

## 述語の表

`<!-- predicates: system -->` か `<!-- predicates: LIB -->` の行は区切りを開き、区切りは次の 0 桁目の ATX の見出し
（`#` から `######` の後ろが空白、タブ、行末のどれかの行）で終わる。LIB は `--mosa` の隣の `lib/` にある `*.pl` の
語幹で、述語の一覧を持たない文面の表 `messages_*` は除く。ほかの名前は誤り。注釈の中身が大文字と小文字を問わず
`predicate` で始まり（`<!-- predicate: lists -->`、`<!-- Predicates: lists -->`）、1 行の
`predicates: NAME` そのものでないものは誤り。印の書き違いで表が確かめられずに通ることはない。区切りの外では、
コードブロックの中と複数行の注釈の中の印は数えない。注釈は `-->` を含む行で終わるので、`<!-->` と `<!--->` も
その行で終わる。その行の印は誤り（印の節を参照）。

区切りに置けるのは表だけ。GitHub がそれぞれの見せ方をする Markdown の形を 1 つずつ追うやり方は、3 度続けて別の形を
見落としたので、検査器は見え方が 1 通りに決まる行だけを通す。区切りのどの行も次のどれかで、ほかの行はすべて誤り。

1. 空の行（空白だけの行は誤り）。
2. 見出しの行。0 桁目の `|` で始まり、バッククォートも `<` も持たず、すぐ下の区切りの行と欄の数が同じ。
3. 区切りの行（`| --- | --- |`。揃えの `:` は書いてよい）。`|` で始まり、見出しの行のすぐ下。
4. 本体の行。区切りの行か本体の行のすぐ下で、0 桁目の `|` で始まり、最初の欄はちょうど 1 つのコードスパン
   `` `name/arity` ``、コードスパンの外に `<` を持たない。

欄は GitHub と同じに数える。直前に `\` のある `|`（`\|`）は欄を分けず、最後の `|` の後ろが空白だけなら次の欄に
しないので、`| a \| b | c |` は 2 欄で `| --- | --- |` が要る。だから区切りの中では、地の文、字下げした行、箇条書きの
項目、引用、次の印でない注釈、コードブロック、区切りの線、setext の下線、生の HTML はどれも誤り。文は印の前に書き、
区切りは ATX の見出しで終える。区切りのどの行にも制御文字（タブ、改ページ、垂直タブ、NUL など 0x20 未満のバイト）は
書けない。行は LF か CRLF か、CommonMark と同じく LF の付かない CR で終わる。区切りの中では、LF の付かない CR で
終わる行も誤り。表は空の行で終わる。本体の行のすぐ下の、本体の行でない行は誤りで、すぐ下に欄の数が同じ区切りの行の
無い見出しの行も誤り。本体の行では、コードスパンの後ろの字（`` `nope/1` (deprecated) ``）、リンク、太字、2 つの
コードスパン、行の中の HTML（`<code>`、`<!-- … -->`、コードスパンの外のどの `<` も）が誤り。引数の数は頭に 0 を
付けない 10 進の数（`between/03` は誤り）。名前はそのまま書く（`` `=../2` ``、`` `\+/1` ``、`` `\==/2` ``、
`` `ひらがな_カタカナ/2` ``）か、Prolog と同じく一重引用符で囲む（`` `','/2` ``）。引用の中で読み替えるのは
`''`（引用符 1 つ）だけで、`\` はそのまま残るので、`\` を含む名前（`\=`、`\==`、`\+`、`=\=`）は引用しないで書く。

```markdown
`between/3` は整数を順に返す。文は印の前に書く。

<!-- predicates: between -->
| 述語 | 意味 |
| --- | --- |
| `between/3` | `between(Low, High, X)`: X は Low から High までの整数。 |
```

`predicates:` の印を 1 つでも持つ章では、生の HTML のタグはどの行でも、区切りの外でも誤り。ここでのタグは `<` の
後ろに英字、`/`、`?`、`!` のどれかが続くもの（`<details>`、`</div>`、`<?php`、`<!DOCTYPE html>`、自動リンクの
`<https://…>`。URL は山括弧を付けずに書く）で、`<!--` は除く。GitHub はタグを HTML として映し、`<details>` や
`<script>` のようなタグは後ろの表を隠す。タグを書いてよいのはコードスパン、コードブロック、`<!-- … -->` の注釈の
中だけで、検査器はこれらを GitHub と同じに読む。

- 0 桁目の `<!--` で始まる行は、`-->` を含む最初の行までの注釈のブロックを始める。ブロック全体が生の HTML で、
  その中の注釈は最初の `-->` か `--!>` で閉じ、`<!-->` と `<!--->` は空の注釈。注釈の後ろの字にはコードスパンも
  `\` の逃がしも無い（`` <!-- a --> `<b>` `` は誤り）。
- 段落の中の注釈は、その行の中の、`-` の直後でない最初の `-->` で閉じる。GitHub は `--->` では閉じない。そうした
  `-->` が無ければ `<!--` はただの字で、注釈ではない（次の項を参照）。
- コードスパンの組みは CommonMark と同じ。組みが変わりうるところからは、次の空の行まで、コードスパンの中のタグも
  誤り。その行で閉じない `` ` `` の並びの後ろ、その行で閉じない `<!--` の後ろ、`` ` `` を持つか次の行へ続きうる
  リンクの行き先、題、ラベル（`[a](…)`、`[a][…]`）の後ろがそう。リンクはそこの `` ` `` を飲むから。`|` を持つ行は欄
  ごとにも読む。GFM は表の行を先に欄に分けるから。
- 字下げ、`>`、箇条書きの印の後ろの `<!--` は、注釈のブロックを始めることも、ただの字のこともあるので、その行から
  次の `-->` までの行は両方の読み方で読み、どちらかでタグが見つかれば誤り。
- コードブロックの行は読まない。囲いは 0 桁目に置く（印の節を参照）ので、GitHub も同じ行をコードとして読む。

注釈のブロックの外の `\<` はただの `<` で、後ろに空白の続く `<`（`X < Y`）はタグではない。区切りの本体の行では、
`` ` `` を持つリンクの行き先、題、ラベルもその欄のコードスパンを終わらせるので、その後ろの `<` は誤り。

1 つのファイルの同じ名前の区切りの項目はすべてまとめて扱うので、章は一覧をいくつかの見出しに分けられる。その名前に
同じ項目を 2 度書くのは誤り。まとめた項目は Mosa と両方向で比べる。Mosa に無い項目と、表に無い述語のどちらも失敗で、
失敗は最初の印の行に両方の一覧を名指す。`system` は組込述語、つまり `predicate_property(H, built_in)` が成り立つ
述語（と、`predicate_property/2` がモジュールの限定として読む `:/2`）から、名前が `$` で始まる内側の補助を除いたもの。
この一覧は `mosatest` の中に組み込んだものなので、`--mosa` は同じ版を出さなければならない。`LIB` は `--mosa` の
隣（シンボリックリンクなら、`mosa` 自身と同じく指す先の隣）の `lib/LIB.pl` を新しい機械に絶対パスで読んだときの
公開リスト。例を動かす `mosa` と同じく `$MOSA_LIB` は見ない。あるが読めないライブラリ（構文の誤り、`module/2` が
無い、別の名前のモジュール）は、その名前とパスと読み込みの誤りを出して失敗する。`use_module/1` や `dynamic/1`
などの指令は組込述語ではないので、印の無い表に書く。章の両版は `predicates:` の印の並びも同じにする。

`--all-tables` を付けると、どの版にも `system` と、その `lib/` のどのライブラリの区切りもなければならない。無い名前は
版ごとに 1 つの誤りとして名指す。どれも並べる参照の章を持つマニュアル全体に使う。
