# 4. 事実と規則

この章では、家族についての事実と規則をファイルに書き、そのファイルを Mosa に読み込ませて、問い合わせをします。

## 手順

1. この章のためのフォルダを作り、シェルをそこへ移します。第 2 章と同じように、ターミナル（Linux では端末、Windows では PowerShell）を開きます。macOS と Linux では、次のように打ちます。

<!-- skip: folder-unix -->
```console
$ mkdir ~/prolog
$ cd ~/prolog
```

Windows では、PowerShell で次のように打ちます。

<!-- skip: folder-windows -->
```powershell
mkdir $HOME\prolog
cd $HOME\prolog
```

`mkdir` はホームフォルダに `prolog` というフォルダを作り、`cd` はシェルをそのフォルダへ移します。後で新しいウィンドウを開いたときは、`cd` の行だけを打てば戻れます。

2. テキストエディタで、フォルダ `prolog` に `家族.pl` という名前のファイルを作り、次の行を書いて保存します。Mosa が読めるのはプレーンテキスト（macOS では「標準テキスト」）だけなので、プレーンテキストとして保存します。
   - macOS の「テキストエディット」では、保存する前に「フォーマット」メニューの「標準テキストにする」を選びます。名前は `家族.pl` のままにします。拡張子をどちらにするか聞かれたら、`.pl` の方を選びます。
   - Windows の「メモ帳」では、「名前を付けて保存」の画面で「ファイルの種類」を「すべてのファイル」にします。そうしないと、ファイルが `家族.pl.txt` になってしまいます。
   - Linux では、プレーンテキストを書けるエディタなら何でも使えます。Ubuntu の「テキストエディター」もその一つです。

   ファイルの 1 行が 1 つの事実です。事実は、無条件に成り立つとする文です。ここでは、1 人目が 2 人目の親であることを表します。

<!-- file: family-file 家族.pl -->
```prolog
親(太郎, 一郎).
親(太郎, 花子).
親(一郎, 桃子).
親(一郎, 次郎).
親(次郎, 三郎).
```

3. ファイル名を付けて Mosa を起動します。Mosa は先にファイルを読み込み、それから `?- ` を出します。太郎が花子の親かどうか、花子が太郎の親かどうかを尋ねて、終わります。

<!-- check: start-with-file -->
```console
$ mosa 家族.pl
?- 親(太郎, 花子).
true.
?- 親(花子, 太郎).
false.
?- halt.
```

こうならずにエラーが出て、シェルに戻ったときは、ファイルの中身が Mosa の読める形になっていません。エラーには、ファイル名と、Mosa が問題に気付いた行と桁が出ます。

- `家族.pl:1:7: 予期しないトークン`（1 行目の 7 桁目）は、ファイルがリッチテキストで保存されていることを表します。テキストエディットやワードパッドはリッチテキストのファイルを `{\rtf1\ansi` で始めるので、Mosa はその 7 字目で止まります。ファイルを開き、プレーンテキストとして保存し直してください（手順 2）。
- それ以外の行と桁は、打ち間違いの場所を指しています。その行と、その前の行を、上の内容と見比べてください。事実はどれも半角のピリオドで終わります。ピリオドが抜けていると、Mosa は次の行の先頭で初めて気付きます。たとえば `親(太郎, 一郎)` の後ろのピリオドがないと `家族.pl:2:1: 予期しないトークン` が出ます。最後のピリオドがないと `家族.pl:6:1: 項が閉じていません` が出ます。ファイルの最後に改行がないときは、`家族.pl:5:10: 項が閉じていません` です。テキストエディットやメモ帳は、最後に改行を足しません。
- 日本語入力をオンにしたまま打つと、`、` `（` `）` `。` のような全角の記号が入ります。Mosa はこれらを区切りの記号として読みません。たとえば `親(太郎、一郎).` と打つと、`家族.pl:1:5: 予期しないトークン` が出ます。名前は日本語入力で打ち、かっこ、コンマ、ピリオドは日本語入力をオフにして半角で打ちます。
- `家族.pl: ファイルを開けません` は、このフォルダにその名前のファイルがないことを表します。macOS と Linux では `ls`、PowerShell では `dir` と打つと、フォルダにあるファイルの本当の名前が分かります。Windows のエクスプローラーは `.txt` のような拡張子を隠すので、`家族.pl` と見えるファイルが、実は `家族.pl.txt` のことがあります。

4. 今度はファイル名を付けずに `mosa` を起動し、`consult/1` でファイルを読み込みます。ファイル名はピリオドを含むので、単一引用符 `'` で囲みます。それから、太郎の子が誰か、三郎の親が誰かを尋ねます。第 3 章と同じように、最初の答えの後で `;` を打ちます。ここから先の例は、どれも `consult('家族.pl')` から始めます。Mosa を起動し直した後でも、そのまま同じように動くようにするためです。読み込み済みのファイルをもう一度読み込んでも、困ることはありません。

<!-- check: consult
consult('家族.pl').
親(太郎, X).
;
親(X, 三郎).
-->
```text
?- consult('家族.pl').
true.
?- 親(太郎, X).
X = 一郎;

X = 花子.
?- 親(X, 三郎).
X = 次郎.
```

5. 太郎が一郎の親かどうかを尋ねます。Mosa はピリオドを付けずに `true` と出して待ちます。太郎についての事実を、まだ全部は見ていないからです。Enter を押して終えます。次に同じことを尋ね、今度は `;` を打ちます。Mosa は残りを見て、ほかに成り立たせる方法がないので `false.` を出します。

<!-- check: not-sure
consult('家族.pl').
親(太郎, 一郎).

親(太郎, 一郎).
;
-->
```text
?- consult('家族.pl').
true.
?- 親(太郎, 一郎).
true
.
?- 親(太郎, 一郎).
true;

false.
```

6. 規則を加えます。`家族.pl` をもう一度開き、下の最後の行を書き足して保存します。規則は、条件が成り立つときに成り立つとする文です。この規則は「X が誰か Y の親で、その Y が Z の親なら、X は Z の祖父母である」と言っています。`:-` の左が結論、右が条件です。「右が成り立つとき、左が成り立つ」と読みます。

<!-- file: family-rule 家族.pl -->
```prolog
親(太郎, 一郎).
親(太郎, 花子).
親(一郎, 桃子).
親(一郎, 次郎).
親(次郎, 三郎).

祖父母(X, Z) :- 親(X, Y), 親(Y, Z).
```

7. Mosa に新しい規則を読ませるため、`consult/1` でファイルをもう一度読み込みます。同じファイルをもう一度読み込むと、前にそのファイルから読んだものは置き換わります。太郎の孫が誰かを、ピリオドが出るまで `;` を打ちながら尋ねます。三郎の祖父母が誰かも尋ねます。

<!-- check: grandparent
consult('家族.pl').
祖父母(太郎, X).
;
;
祖父母(X, 三郎).
;
-->
```text
?- consult('家族.pl').
true.
?- 祖父母(太郎, X).
X = 桃子;

X = 次郎;

false.
?- 祖父母(X, 三郎).
X = 一郎;

false.
```

8. `halt.` と打って終わります。

## 何が起きたか

ファイルに書いたのは節（せつ）です。節は事実か規則のどちらかです。`親(太郎, 一郎).` のような事実は、無条件に成り立ちます。`祖父母(X, Z) :- 親(X, Y), 親(Y, Z).` のような規則は、`:-` の後のゴールがすべて成り立つときに成り立ちます。名前と引数の数が同じ節が集まって、1 つの述語になります。`親/2` は 5 つの節、`祖父母/2` は 1 つの節でできています。`X` のような変数が同じ値を表すのは、その変数がある節や問い合わせの中だけです。ですから、問い合わせ `祖父母(太郎, X)` の `X` と、規則の `X` は別の変数です。

`mosa 家族.pl` も `consult('家族.pl')` も、ファイルを読み込みます。Mosa は、起動したフォルダでファイルを探します。ファイル名は全部書く必要があります。`.pl` を省くと、Mosa はファイルを見つけられません。

<!-- check: no-extension -->
```text
?- consult(家族).
家族: ファイルを開けません
false.
```

ファイルの中身に誤りがあるときは、手順 3 の後の一覧のように、Mosa は誤りに気付いた行と桁を出します。`家族.pl` を変えずに、わざと誤りを作って試せます。手順 2 の事実を、1 つ目の事実のピリオドを抜いて、`誤字.pl` という名前でもう一度保存します。Mosa は `親(太郎, 一郎)` を読んだ後、次の行へ進みます。ピリオドがないので、そこに `親` は続けられません。そのため、エラーは 2 行目の 1 桁目を指し、`mosa` はシェルに戻ります。

<!-- file: typo-file 誤字.pl -->
```prolog
親(太郎, 一郎)
親(太郎, 花子).
親(一郎, 桃子).
親(一郎, 次郎).
親(次郎, 三郎).
```

<!-- check: typo -->
```console
$ mosa 誤字.pl
誤字.pl:2:1: 予期しないトークン
```

Mosa は問い合わせに答えるとき、述語の節を上から順に試します。合う節があると答えを出し、その下にまだ試していない節があることを覚えておきます。`;` を打つと、Mosa は最後に選んだところまで戻って、次の節を試します。この戻り方をバックトラックと呼びます。

手順 7 で、Mosa が `祖父母(太郎, X)` の答えを見つけた順は次のとおりです。

1. 規則の `X` は `太郎` になり、`Z` は問い合わせの `X` を表します。規則の 1 つ目のゴール `親(太郎, Y)` は最初の事実に合うので、`Y = 一郎` になります。
2. 2 つ目のゴールは `親(一郎, Z)` になります。これは事実 `親(一郎, 桃子)` に合うので `Z = 桃子` になり、Mosa は 1 つ目の答え `X = 桃子` を出します。
3. `;` を打つと、Mosa は `親(一郎, Z)` まで戻り、`Z = 次郎` を見つけます。これが 2 つ目の答え `X = 次郎` です。
4. もう一度 `;` を打つと、1 つ目の引数が `一郎` の事実はもうないので、Mosa はさらに `親(太郎, Y)` まで戻り、`Y = 花子` を見つけます。1 つ目の引数が `花子` の事実はないので、`親(花子, Z)` は失敗します。試すものがなくなったので、`false.` を出します。

ピリオドの付かない `true` や答えは、Mosa にまだ試す節が残っていることを表します。ほかに答えがあるという意味ではありません。手順 5 ではほかに答えがなかったので、`;` の後は `false.` でした。

## 練習問題

1. 次郎の親は誰ですか。ファイルを読み込んで尋ね、`;` を 1 回打ってください。
2. `子(X, Y)` が「X は Y の子である」ときに成り立つ述語 `子/2` を規則で書き足し、それを使って太郎の子を尋ねてください。

### 答え

1. 一郎です。`;` の後、Mosa はほかの親を見つけられません。

<!-- check: exercise-parents
consult('家族.pl').
親(X, 次郎).
;
-->
```text
?- consult('家族.pl').
true.
?- 親(X, 次郎).
X = 一郎;

false.
```

2. Y が X の親なら、X は Y の子です。この規則を `家族.pl` に書き足します。

<!-- file: family-child 家族.pl -->
```prolog
親(太郎, 一郎).
親(太郎, 花子).
親(一郎, 桃子).
親(一郎, 次郎).
親(次郎, 三郎).

祖父母(X, Z) :- 親(X, Y), 親(Y, Z).

子(X, Y) :- 親(Y, X).
```

それから、もう一度読み込んで尋ねます。

<!-- check: exercise-child
consult('家族.pl').
子(X, 太郎).
;
-->
```text
?- consult('家族.pl').
true.
?- 子(X, 太郎).
X = 一郎;

X = 花子.
```
