### H-01. IrTerm destruction allocates inside noexcept, so a bad_alloc there ends the process (read)
- Status: done (b16573d6; test fixed in bf7601e0). CI run 44849948624 failed `ir_release` on GCC (x86-64) and MSVC: the test read its live-block count after building the message argument, and those compilers evaluate the arguments right to left, so the message's own allocation was counted. The test now reads the count first; the release code is unchanged. `release_deep` no longer allocates: when it goes down into a node with children, it takes the children out, makes that node the return mark, and parks the rest of the list above in the mark's `args`. The mark is the last item of that list, so when the current list is gone it takes the list above back from the mark and drops the mark. Only `std::vector::swap` and `pop_back` run, and a node it drops always has empty `args`, so `~IrTerm` does not recurse. Depth 64 and less still recurse natively (ADR 0011 amendment 1), and the IR does not change. The new `tests/cpp/ir_release_test.cpp` replaces the global `operator new` of its own executable and counts calls while a tree is released: before the change the five deep shapes (lists and first-child chains of 100,000, chains of small trees of 20,000, by destruction and by move assignment) allocated 1 to 21 times; now none allocates, and every block is returned. The shallow tree and the self-child move `term = std::move(term.args[1])` allocate nothing before and after. Also clean under ASan and UBSan (the test and `ir.cpp` alone); releasing a list of 1,000,000 takes 15.4 ms instead of 19.0 ms. Triage: `release_deep` builds a `std::vector<std::vector<IrTerm>>` work stack. It is called from `IrTerm::release` (noexcept) and from the noexcept move assignment, for any tree deeper than 64. A `bad_alloc` there calls `std::terminate` instead of the heap-limit stop of ADR 0010. Not run: macOS does not enforce `ulimit -v`.
- Where: `src/core/ir.cpp:46-56` (`release_deep`), `67-74` (`IrTerm::release`), `90-102` (move assignment).
- Expected: destruction allocates nothing, for example by reusing the `args` buffers as the work list.
- Standard: not in 13211-1.
- Wave: W3. Gate: none (the caller's call). The fix keeps the IR and the ADR 0011 amendment 1 rule, which names IrTerm destruction (native recursion to depth 64, explicit stack below), and it is what ADR 0010 "Stop" already requires, so the plan's ADR gate does not seem needed.

### H-04. The standard order of cyclic terms is not transitive, so sort/2 depends on the input order ✔
- Status: done (a5148eed, 9eecebd3 and 3ad5c4b2 for ADR 0029, approved by the owner's request to work on H-04; c1113c90 and 7f6bfa20 for the code). Translation time grows about quadratically, but it is small: 0.03 s at 2,000 keys, 0.98 s at 16,000. Each `kKey` array repeats all keyless clauses.
- Where: `src/codegen/emit.cpp:199-236` (`dispatch_text`)
- Repro: 2,000 facts `f(k<i>, i)`, and 300,000 calls in a failure-driven loop. Under `mosa`, the last key takes 343 ms and the first 345 ms. In the `mosac build` executable, the last key takes 682 ms and the first 97 ms. With 100 keyless clauses in front of 4,000 keyed ones, each `kKey` array has 101 entries, and `muser.cpp` is 12.2 MB against 3.8 MB without them.
- Expected: constant-time dispatch for large tables (a sorted table or a hash of atom ids), and keyless clauses that are not copied into every key.
- Standard: not in 13211-1.
- Wave: W9. Gate: none.
