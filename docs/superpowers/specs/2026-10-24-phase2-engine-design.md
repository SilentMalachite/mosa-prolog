# フェーズ2 実行の核 設計

日付: 2026-10-24
状態: 承認済み（2026-10-24）

## 意図

フェーズ2は、フェーズ1の項の上で Prolog のゴールを実行する。読む人は、このあと段階ごとに実装するエージェントと、ADR 0003 を承認する浩さんである。

成功は機械的に判定する。`nrev` と `queens` が決まり、段階 A の規格 Examples と、フェーズ2へ繰り上げた算術の Examples が全部通る。途中の段階は、その段階のテストが CTest で通ることで判定する。

実行の形は仕様第6節のとおり、節を継続渡しの中間表現に落とし、トランポリンで回す。この中間表現はフェーズ6の `mosac` も読む。ここで決めた表現は、ADR を書き直して承認するまで変えない。

## 規模

設計はこの文書 1 枚である。実装は下の 10 段階で、段階ごとにセッションを分ける。1 段階は「1 つのファイル群」に収める。算術の評価関数はファイルを分けてよい。分けたファイルも、同じ段階の終わりにまとめてテストが通る。

## 目標

- 継続渡しの中間表現、節コンパイラ、第1引数のインデクシング
- トランポリンの実行ループ、選択点、条件付きトレイル、カット、`catch/throw`
- 段階 A の組込述語。一覧は「決めたこと」に書く
- 算術。`is/2`、算術比較 6 個、仕様第7節の段階 B の評価関数一式
- `consult/1` と、承認した画面どおりの最小 REPL、`-g` と `-t halt`
- `mosatest` が `test/3` を実行する
- `tests/pl/nrev.pl` と `tests/pl/queens.pl` が通る

## 非目標

- アトム処理（`atom_length/2` から `atom_number/2`）。フェーズ3
- ストリーム、`open/3`、`write/1`、`read_term/3`、`op/3` をゴールとして呼ぶこと。フェーズ3
- `assert` 系、`clause/2`、`abolish/1`、`findall/3`、`bagof/3`、`setof/3`
- `dynamic/1`、`discontiguous/1`、`multifile/1`、`initialization/1`、`include/1`、`ensure_loaded/1`、`[File]`、`set_prolog_flag/2`、`current_prolog_flag/2`
- モジュール、`mosac`、差分テスト、GC、多倍長整数、`BIG` タグの生成
- メッセージ目録（`lib/messages_ja.pl`）。フェーズ5
- 日本語ファイル名を完了条件に含めること。パスはバイト列のまま開く。テストのパスは ASCII
- `bench/` の計測。`nrev` と `queens` は正しさだけを見る
- REPL のバナーとヘルプ
- `include/mosa/mosa.hpp` に、決めた 4 関数以外の署名を足すこと
- `runtime.hpp` を生成コード向けに広げること

## 失敗になるもの

- 中間表現を後から WAM や「節の項を毎回歩く」形へ載せ替える
- ADR 0003 より先に中間表現のコードを書く
- Examples を通すために期待値を弱める、スキップする、実装に合わせて書き換える
- 既定のユニフィケーションに出現検査を入れて、`X = f(X)` を失敗させる
- 算術のオーバーフローを浮動小数や多倍長へ逃がす
- フェーズ1の往復テストを壊す
- 選択点ができる前に束縛して、失敗したときに束縛を残す

## 制約

- 言語は C++20。依存は標準ライブラリと CMake だけ
- 警告はフェーズ0と同じくエラー扱い
- 1 関数 60 行以内、1 ファイル 800 行以内。超える前にファイルを分ける
- 識別子は英語。コメント、コミット、文書は日本語。コメントは理由だけを書く
- Prolog の失敗と `throw/1` は値と機械の状態で表す。C++ の例外は `ResourceLimit` だけ
- OS 依存の `#ifdef` は `src/platform/` 以外に書かない
- コミットメッセージは `[phase2] ` で始まる日本語 1 行とし、何を確認したかを含める
- 各段階の終わりに `cmake --build build && ctest --test-dir build` を通す。`docs/STATUS.md` は 15 行以内
- Cell のタグとビット配置は ADR 0001 と ADR 0002 のまま。変えない
- この設計の承認を、ADR 0003 の承認とする。実装の第1段階で ADR を `docs/adr/0003-execution-ir.md` に置く

## アプローチ

実行の範囲と画面と読み込みの規則は、会話で決まっている。選んだのは実行の形である。

**1. 継続渡しの中間表現を、先に全部決めてから段階で積む（採用）**

節は継続を最後に持つ形へコンパイルする。実行ループはトランポリンである。選択点、カット、`catch`、組込述語の呼び出しは ADR に先に書き、実装の途中で表現を足さない。コードは下の段階順に積む。最初に動くプログラムは事実 1 つで、`nrev` はその数段階あとである。

採用の理由は、仕様第6節がこの形を `mosac` との共通入力にしていることと、フェーズ1で項を最初から Cell にしたのと同じで、後からの載せ替えを避けるためである。

**2. 節の項を実行のたびに歩く（不採用）**

中間表現を作らず、`:-` と `,` を実行時にたどる。`nrev` は早く動く。フェーズ6で別の表現へ載せ替えることになる。

**3. WAM の命令列と環境スタック（不採用）**

環境スタックと命令列が中間表現になる。仕様の `mosac` が呼ぶ関数は、引数と継続を受け取ってループする形なので、この命令列は入力にならない。

## 決めたこと

ここより上の目標と非目標、および次の挙動は、会話で合意したものである。

算術はフェーズ2の完了に含める。範囲は `is/2`、`=:=` `\=` `<` `=<` `>` `>=`、仕様第7節の段階 B に列挙された評価関数一式である。整数は 64bit のままである。オーバーフローは `evaluation_error(int_overflow)`、ゼロ除算は `evaluation_error(zero_divisor)` である。アトム処理はフェーズ3のままである。

段階 A の述語は次のとおり、全部フェーズ2に含める。

- 単一化と型: `=/2`、`\=/2`、`unify_with_occurs_check/2`、`var/1`、`atom/1`、`integer/1`、`float/1`、`atomic/1`、`compound/1`、`nonvar/1`、`number/1`、`callable/1`、`is_list/1`
- 項の順序: `@</2`、`@=</2`、`@>/2`、`@>=/2`、`==/2`、`\==/2`、`compare/3`
- 項の分解: `functor/3`、`arg/3`、`=../2`、`copy_term/2`、`term_variables/2`
- 制御: `true/0`、`fail/0`、`false/0`、`!/0`、`,/2`、`;/2`、`->/2`、`*->/2`、`catch/3`、`throw/1`、`call/1` から `call/8`、`\+/1`、`once/1`、`repeat/0`、`halt/0`、`halt/1`

`is_list/1` と `*->/2` は仕様が段階 A に入れている非 ISO の述語である。フェーズ2に含める。

画面は次のとおりである。

- 引数のファイルは左から順に読む。そのあと、`-g` のゴールかプロンプトである
- 対話では、次の解があるとき `;` で次へ進み、改行でそのゴールを終える。名前のある変数だけを出す。名前の無い成功は `true.`、失敗は `false.`
- 次の解が無い成功は、待たずにピリオドまで書いて終える
- `-g` と `-t halt` は最初の解だけ出して終わる。成功は終了コード 0、失敗は 1、捕捉されない例外は 2
- 端末で `-t halt` が無い `-g` は、解を見終わったあと `?-` に戻る
- 端末でないのに `-g` が無いときは、使い方を標準エラーに出して終了コード 1
- 起動時のファイルが読めないときは、プロンプトを出さず終了コード 1
- 対話中の捕捉されない例外は、警告を出して `?-` に戻る。その場ではプロセスを終わらせない
- 例外の文は `警告: ゴールは例外を送出しました: ` に、投げられた項をライタで続けたものである

読み込みは次のとおりである。

- ファイルは C++ がバイト列で読み、リーダに渡す。Prolog のストリームは使わない
- 受け付けるのは節と `:- op(優先度, 指定子, 名前).` だけである。それ以外の `:-` と、`-->` で書かれた節は読み込みを失敗させる
- `op` の宣言は、そのファイルの残りと、その後のプロンプトに残る。プロンプトの `:- op(...).` も同じ宣言である
- ゴールとしての `op/3` はフェーズ3まで呼ばない
- ファイルが定義する述語は、読み込みのときに置き換える。二度読んでも解は倍にならない
- 同じファイルの中で述語の節が離れていたら、読み込みを失敗させる
- 別のファイルが同じ述語を定義したときは、あとから読んだほうを残す
- `consult/1` はプロンプトから呼べる。引数はアトム 1 つで、パスである

段階の順は次のとおりである。

1. ADR 0003 を置く。中間表現のコードはこの後だけ書く
2. トレイルを機械へ移し、事実 1 つが成功するループを動かす
3. 規則、連言、複数節、選択点
4. カットと `->/2`
5. `catch/throw`
6. 第1引数のインデクシング
7. 段階 A の残りの述語
8. 算術を実行ループへつなぐ
9. `consult`、プロンプト、`-g`、`mosatest` の `test/3`
10. 段階 A と算術の Examples、`nrev`、`queens`

組込述語の計算そのものは、実行ループより先に C++ のテストで確かめてよい。Prolog の Examples は、ゴールを実行できるようになってから通す。

## 実装者への決定

会話で埋まっていなかった箇所は、次のとおり決める。承認時にここだけを読み返せば足りる。

1. 版文字列は、第10段階が通りフェーズ2完了を STATUS に書くコミットで、`mosa 0.0.1 (phase 2)` に変える。それより前は `phase 1` のままにする。
2. `include/mosa/mosa.hpp` の 4 関数をフェーズ2で実装する。`Machine::create`、`consult`、`query`、`halt` である。REPL と `mosatest` はこれを使う。5 つ目の関数は足さない。`query` は、1 つのゴールを実行し、次の解を求める操作と、解の束縛と、失敗と、例外と、`halt` の終了コードを返す。プロンプトの `;` は、この「次の解」を呼ぶ。
3. ヒープのゴール枠は項ではない。中身は、述語のアトム番号、アリティ、カット境界、継続枠の番地、引数セルである。継続が無いクエリの終わりは、継続枠が無いことで表す。フェーズ7の GC はゴール枠を印の起点に含める。この文を ADR 0003 の影響に書く。Float と IntBox のペイロードと同じく、ゴール枠を項として走査しない。
4. 選択点は、次に試す節、ヒープ使用量、トレイル使用量、やり直すゴール枠、カット境界を持つ。`catch` の枠は同じスタックに積む別種で、ボールのパターン、回復ゴール、キャッチの外の継続、ヒープとトレイルと選択点の水位を持つ。
5. トレイルは機械が持つ。束縛した REF のうち、現在の選択点のヒープ水位より前にあるものだけを積む。水位より新しいセルは、ヒープ使用量を戻すと消える。ユニフィケーションが失敗したときは、その呼び出しで積んだ分と、その呼び出しの開始時のヒープ使用量まで戻す。成功したときは束縛もトレイルも残す。選択点まで戻すのは実行ループである。フェーズ1の `unify` は、成功時にトレイルの記録を捨てている。フェーズ2では捨てない。
6. 節が 1 つなら選択点を作らない。節が複数のあいだ、インデクシングより前の段階は、残りの節があるときに選択点を作る。インデクシングの後は、第1引数の候補が 1 つなら選択点を作らない。候補は、変数のヘッドを常に含める。定数、リスト、関手は、同じものか変数のヘッドだけを含める。落としてはならない節を落とすより、余分な候補を残す。
7. カット境界は、述語に入ったときの選択点スタックの高さである。`!/0` は、それより新しい選択点を捨てる。`call/1` から `call/8`、`catch/3` のゴール、`\+/1`、`once/1` は、入ったときの高さをその中のカット境界にする。中のカットは外へ出ない。
8. `;/2` は選択点で左右を分ける。左が `->/2` のときは、条件が成功したら右辺の else を捨て、条件が失敗したら else を実行する。単独の `->/2` は、条件が失敗したらゴールも失敗する。`*->/2` は条件の解を捨てない。条件の各解について then を実行する。条件が一度も成功せず、`;/2` の右があるときだけ、その右を実行する。
9. `throw/1` は、ボールを `copy_term` してから選択点を戻し、キャッチのパターンと単一化する。単一化できなければ、さらに外のキャッチへ進む。キャッチが無ければトップレベルへ届く。`throw` は C++ の例外にしない。
10. ヒープ上限を超えた `ResourceLimit` は、Prolog の `catch` では捕まらない。トップレベルが捕捉する。バッチなら終了コード 2、対話なら警告を出してプロンプトへ戻る。尽きかけのヒープでエラー項を組み立てないためである。
11. 未定義の述語は `existence_error(procedure, 名前/アリティ)` を投げる。`unknown` は `error` のままとする。フェーズ2ではフラグを変える述語が無い。
12. エラー項は `error(Formal, context(PI, Extra))` である。`Extra` は未束縛変数とする。テストは Formal だけを比べ、Context は比べない。Formal はヘルパで作り、呼び出し側にアトム名の文字列を直書きしない。引数検査の順は、規格のその述語の Errors の列挙順とする。検査が終わる前に束縛しない。
13. `integer_rounding_function` の値は `toward_zero` に固定する。`//` と `rem` は 0 へ向かって丸める。`div` と `mod` は負の無限大へ向かって丸める。フラグを読む述語はフェーズ3まで無い。この値は、フェーズ3の `current_prolog_flag/2` が返す値になる。
14. `float_overflow`、`float_zero_div`、`float_undefined` の既定は `error` である。フェーズ2では変えない。整数のゼロ除算と、このフラグが `error` のときの浮動小数のゼロ除算は `evaluation_error(zero_divisor)` である。浮動小数のオーバーフローは `evaluation_error(float_overflow)`、`sqrt(-1)` のような未定義は `evaluation_error(undefined)` である。
15. 評価関数の結果が `int64` に収まらないときは `evaluation_error(int_overflow)` である。浮動小数へは変換しない。`max_integer` は `2^63-1`、`min_integer` は `-2^63` である。片方が浮動小数のときの整数との演算は、整数を浮動小数へ変換してから計算する。`/` の結果は浮動小数である。
16. 算術の、規格の文と Corrigenda を読んでも期待値が一つに決まらない箇所は、実装せず `docs/iso-notes.md` に条番号と「A か B か」の質問を 1 つ書いて止まる。質問を推測で埋めない。
17. 変数どうしの標準順序は、ヒープ上の番地の若いほうを先にする。Examples の期待値に、変数どうしの大小を書かない。浮動小数の類は整数の類より前である。同じ類の数は数値として比べる。`-0.0` と `0.0` は等しい。`NaN` はどの浮動小数より後ろとする。アトムは UTF-8 バイト列の辞書順とする。
18. 循環項は `=/2` が作る。`X = f(X)` は成功する。`unify_with_occurs_check/2` は循環になる束縛を失敗させる。`is_list/1` は、末尾が `[]` の有限リストだけを成功させ、循環は失敗させる。`copy_term/2` は循環を保って複製する。`term_variables/2` と標準順序は、訪れた複合項の番地を覚えて止まる。循環どうしの標準順序は Examples に使わない。C++ テストでは、止まることだけを見る。
19. ライタは、名前表にある REF に、束縛を追うより先に出会ったら、その名前を書く。答えの表示は、変数の束縛先から書き始める。したがって `X = [X]` は `X = [X]` と出る。名前の無い循環は、複合項の番地を覚え、再訪したところを `_` と書く。フェーズ1の往復は、未束縛の名前付き変数だけを通すので、この変更のあとも通る。
20. 答えに出す変数は、ゴールのテキストに現れた順の、名前のある変数である。値は束縛を外した項である。自分より前の変数の値として既に出ている未束縛変数は、重ねて出さない。`X = Y` で両方が未束縛なら `X = Y.` と出して、`Y` は出さない。`X = Y, Y = 1` は `X = 1, Y = 1.` と出る。
21. プロンプトは `?- ` である。項が完成するまで読み、未完成の改行は続きを待つ。空行は無視する。ピリオドの規則はリーダと同じである。`;` の待ちでは、`;` で次の解、改行で終了する。終了するときは、その解の行末に `.` を書く。次が無いのに `;` を受けたら `false.` と書く。`halt/0` は終了コード 0、`halt/1` の整数はその終了コードである。`halt` はプロセスをその場で終わらせず、機械を止めて `main` がコードを返す。入力の終わりは終了コード 0 である。
22. コマンドラインは `mosa [ファイル...] [-g ゴール] [-t halt]` である。`--version` がどれかの引数と完全一致するときは、版だけを出して終了コード 0 とする。`-g` と `-t` はそれぞれ 1 回までである。`-t` の値は `halt` だけを受け付ける。ゴールのテキストは 1 引数で、リーダが 1 項として読めるものとする。使い方の文は `mosa: 使い方: mosa [ファイル...] [-g ゴール] [-t halt]` とする。標準入力が端末でないときの `-g` は、`-t halt` の有無にかかわらず、最初の解だけ出して終了コード 0、1、2 で終わる。`;` は読まない。これはレビューで空いていた箇所なので、ここで決める。解を全部出すと `repeat/0` で止まらない。
23. 起動時の構文エラーは `パス:行:列: 理由` を標準エラーに書く。理由は `SyntaxReason` ごとに固定する。`IncompleteTerm` は `項が閉じていません` である。ほかは、不正な UTF-8、使えない文字、引用が閉じていない、コメントが閉じていない、不正なエスケープ、整数が範囲を超えている、予期しないトークン、引数が多すぎる、とする。
24. 受け付けない指示は `パス: この指示はフェーズ2では使えない: ` のあとに、その項をライタで書く。節が離れているときは `パス: 述語 名前/アリティ の節が離れている` と書く。ファイルを開けないときは `パス: ファイルを開けません` と書く。これらは起動時なら終了コード 1、プロンプトの `consult/1` なら同じ文を出してゴールを失敗させる。
25. `:- op(優先度, 指定子, 名前).` の名前は、アトム 1 つか、アトムのリストである。リストなら要素ごとに、フェーズ1の `OperatorTable::define` へ渡す。`define` が拒否したら読み込みを失敗させ、拒否の理由を 1 行で標準エラーに書く。優先度 0 は、フェーズ1と同じく、その名前と指定子の組を消す。
26. 選択点スタックが空でないときに、既存の述語を置き換える `consult` は失敗させる。文は `パス: 実行中の述語は置き換えられない` とする。トップレベルのゴールとゴールのあいだではスタックは空である。
27. `mosatest` の `--roundtrip` と `--version` はフェーズ1のまま残す。引数がファイルかディレクトリのときは、`test(名前, ゴール, 期待).` を実行する。ディレクトリでは、直下の `*.pl` のうち `syntax.pl` を除いて、ファイル名の順に実行する。`syntax.pl` は往復のデータのままで、`test/3` を足さない。
28. テストファイルはリーダで項にする。`test/3` の事実はテストとして取り出す。それ以外の節は機械へ入れる。`clause/2` は使わない。各テストの前に、ヒープ使用量とトレイルと選択点を、そのファイルを読み終わった直後の状態へ戻す。プログラムの節は残る。
29. 期待値は `true`、`fail`、`error(Formal)`、`solutions([束縛, ...])` の 4 種である。`solutions` の中の束縛は、ゴールに書いた名前で `名前 = 値` とする。解の順は深さ優先で、節の並び順とする。1 つの解の中の名前の順は、ゴールのテキストに現れた順とする。`error` は投げられた Formal だけを、ユニフィケーションで比べる。
30. `nrev` は次のプログラムで、`nrev([1, 2, 3], R)` の最初の解が `R = [3, 2, 1]` であることとする。

```prolog
nrev([], []).
nrev([H|T], R) :- nrev(T, S), append(S, [H], R).

append([], L, L).
append([H|T], L, [H|R]) :- append(T, L, R).
```

31. `queens` は次のプログラムで、`queens(4, Qs)` の最初の解が `Qs = [2, 4, 1, 3]`、`queens(8, Qs)` の最初の解が `Qs = [1, 5, 8, 6, 3, 7, 2, 4]` であることとする。画面の `queens(8, Qs)` は、この最初の解を出す。

```prolog
range(From, To, []) :- From > To, !.
range(From, To, [From|Rest]) :-
    Next is From + 1,
    range(Next, To, Rest).

take(X, [X|Xs], Xs).
take(X, [Y|Ys], [Y|Zs]) :- take(X, Ys, Zs).

perm([], []).
perm(Xs, [Y|Ys]) :- take(Y, Xs, Zs), perm(Zs, Ys).

safe([]).
safe([Q|Qs]) :- safe(Qs), \+ attack(Q, Qs).

attack(Q, Qs) :- attack(Q, 1, Qs).
attack(Q, N, [Q1|_]) :- abs(Q - Q1) =:= N.
attack(Q, N, [_|Qs]) :- N1 is N + 1, attack(Q, N1, Qs).

queens(N, Qs) :- range(1, N, Ns), perm(Ns, Qs), safe(Qs).
```

32. 標準入力が端末かどうかは `src/platform/` の関数 1 つに置く。フェーズ2で `src/platform/` に置く処理は、これだけである。
33. C++ テストは領域ごとに実行ファイルを分け、`tests/cpp/harness.hpp` は 50 行を超えて伸ばさない。Prolog の Examples は、対応する述語の実装より先に `tests/pl/` へ写す。写した時点では失敗してよい。その段階の終わりに通す。
34. コミットは段階の中でも論理単位ごとに分けてよい。1 コミットに複数段階をまとめない。
