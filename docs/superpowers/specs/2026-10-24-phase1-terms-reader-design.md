# フェーズ1 項とリーダ・ライタ 設計

日付: 2026-10-24
状態: 承認済み（2026-10-24）

## 意図

フェーズ1は、Prolog の実行をまだ持たない状態で、項の表現と、規格第6章の構文の読み書きを動かす。読む人は、このあとフェーズ1を1段階ずつ実装するエージェントと、ADR 0001 を承認する浩さんである。

成功は機械的に判定する。`mosatest --roundtrip tests/pl/syntax.pl` が終了コード 0 で終わり、同ファイルの日本語アトムの往復を含む。途中の段階は、その段階の C++ テストが CTest で通ることで判定する。

項は最初から Cell である。リーダがヒープに置き、ライタがそれを書く。読み書きのあいだに別の構文木は作らない。

## 規模

設計はこの文書 1 枚である。実装は下の 8 段階で、段階ごとにセッションを分ける。1 段階は「1 つのファイル群」に収める。Unicode の表、lexer、演算子表の 3 段階は ADR 0001 の承認前に着手できる。Cell 以降は承認後である。

## 目標

- Cell、ヒープ、アトム表、トレイル、出現検査なしのユニフィケーション
- Unicode 18.0.0 の文字分類表を生成し、`src/unicode_tables.inc` にコミットする
- lexer、Pratt 法のリーダ、`write_term` に相当するライタ
- 演算子表と、ISO コアの既定演算子。`op/3` に相当する C++ の登録
- `tests/pl/syntax.pl` をデータとして置き、`mosatest --roundtrip` で往復させる
- 壊れた入力は、行・列・トークン・理由を持つ値で返す。検査は `tests/cpp/` に置く

## 非目標

- 実行ループ、選択点、カット、`catch/throw`、`consult/1`、`test/3`、REPL
- `read_term/3` と `write_term/3` を Prolog の述語として公開すること。エラー項 `error/2` の組み立てと `throw/1`
- `set_prolog_flag/2`、`char_conversion/2`、全角記号モード、ファイルストリーム、Windows コンソール
- ライタの `numbervars`、`max_depth`、空白の細かな指定オプション
- モジュールごとの演算子表、`:` 演算子（13211-2）
- 出現検査、循環項の検出、GC、多倍長整数、`BIG` タグの生成
- `include/mosa/mosa.hpp` の 4 関数に署名を書くこと。`runtime.hpp` への Cell の公開
- 版文字列を、フェーズ1完了のコミットより前に変えること

## 失敗になるもの

- 往復を通すために、リーダかライタの期待値を実装へ合わせて弱める
- 項の途中表現を Cell 以外に持ち、後から載せ替える
- 承認前に Cell を実装する
- 選択点スタックや実行ループを、ユニフィケーションのついでに入れる
- GNU Prolog や SWI の演算子表を、ISO コアの正本にする
- 負の整数リテラルがあるとみなして、`-42` を整数の負の値として読む

## 制約

- 言語は C++20。依存は標準ライブラリと CMake だけ。`reinterpret_cast`、生の `new` と `delete`、C 配列、マクロは使わない。浮動小数と整数ビット列の変換は `std::bit_cast` を使う
- 警告はフェーズ0と同じくエラー扱いにする
- 1 関数 60 行以内、1 ファイル 800 行以内。超える前にファイルを分ける
- 識別子は英語。コメント、コミット、文書は日本語。コメントは理由だけを書く
- Prolog の失敗と構文エラーは値で返す。C++ の例外は、ヒープ上限を超えたときだけ使う
- OS 依存の `#ifdef` は `src/platform/` 以外に書かない。フェーズ1では `src/platform/` にソースを置かない
- コミットメッセージは `[phase1] ` で始まる日本語 1 行とし、何を確認したかを含める
- 各段階の終わりに `cmake --build build && ctest --test-dir build` を通す。`docs/STATUS.md` は 15 行以内で更新する
- Cell の表現を ADR 0001 から変える部分は、実装の前に ADR 0002 へ写す。この設計の承認を、ADR 0002 の承認とする。別の確認はしない

## アプローチ

構文の範囲と成功条件は会話で一つに決まっている。選んだのは作業の順番である。

**1. 承認の前後で区切る（採用）**

ADR 0001 が承認されるまで Cell は書かない。そのあいだに Unicode の表、文字分類、lexer のトークンテスト、演算子表を作る。承認のあと、Cell とヒープとアトム、ユニフィケーション、リーダ、ライタ、`mosatest --roundtrip` の順に積む。`syntax.pl` は往復が実行できるコミットで追加し、そのとき CTest に載せる。各段階の終わりで、その段階のテストが通る。

採用の理由は、Cell の実装が ADR の承認後に限られていることと、1 回の作業で 1 段階を終える規則が、下から積む順番と合うことである。

**2. 承認までコードを書かない（不採用）**

設計のあと、ADR 0001 が承認されるまで実装に入らない。最初のコードは Cell になる。承認が遅れているあいだ、成果は設計文書だけになる。

**3. 例文を最初の成果物にする（不採用）**

`syntax.pl` を表や Cell より先に置く。目標のファイルは最初から読める。リーダが出来るまで、その例が通ることはテストでは示せない。

一時的な構文木を後から Cell に載せ替えるやり方は、項は最初から Cell にするという合意と合わないため、候補から外した。

## 決めたこと

ここより上の目標と非目標、および次の挙動は、会話で合意したものである。

判定は `mosatest` が行う。中身は C++ で、メモリ上の文字列にリーダとライタを直接呼ぶ。`tests/pl/syntax.pl` はゴールの列ではなく、項の例を並べたデータである。

成功は次の意味である。例のテキストを読み、演算子表を使って `quoted(true)` かつ `ignore_ops(false)` で書き、その出力の末尾にピリオドを足してもう一度読む。2 回目の項が 1 回目と同じなら成功である。名前のある変数は、例に書いた名前で対応づける。`_` は名前に入れず、出現ごとの別変数とする。空白や引用の見た目を固定したい例だけ、期待する文字列をその場に書く。

ユニフィケーションそのものは `tests/cpp/` で見る。`syntax.pl` は構文の往復だけを見る。

演算子表はリーダに渡すオブジェクトであり、モジュールには属さない。各ケースは ISO の既定表から始め、そのケース内の `:- op(優先度, 指定子, 名前).` だけを足す。ケースをまたいで演算子は残らない。

日本語の往復は同じファイルに置く。最低限、`親(太郎, 一郎).` と、BMP 外の `𠮷` を含める。

リーダが受理する構文は、仕様第3節の第6章相当である。名前、変数、引用アトム、整数、浮動小数、文字列、リスト、中括弧、演算子式、`end_of_file`、コメント、エスケープ（`\x`、`\u`、`\U`、行をまたぐ継続、ISO の記号エスケープと 8 進）、`0b` `0o` `0x` `0'c`、桁の間の `_` を含む。文字列の解釈は `codes`、`chars`、`atom` の 3 つで、既定は `codes` である。文字変換は恒等のままにする。

ライタのオプションは `quoted` と `ignore_ops`、それに読み取り時の変数名である。数は最短の往復表現で、小数点を含め、指数は `e` である。

壊れた入力は、行、列（コードポイント単位、1 始まり）、問題のトークン、理由を持った失敗として返す。往復が通ることが完了条件で、壊れた入力の検査は `tests/cpp/` に置く。

Unicode の一般カテゴリは字句分類のために生成してコミットする。東アジア幅も同じ生成で表に入れる。幅を使う処理はフェーズ1には書かない。

## 実装者への決定

会話で埋まっていなかった箇所は、次のとおり決める。承認時にここだけを読み返せば足りる。

1. Unicode の版は 18.0.0 とする。今日時点の安定版である。`tools/gen_unicode_tables.py` は標準ライブラリだけで書き、`https://www.unicode.org/Public/18.0.0/ucd/UnicodeData.txt` と `EastAsianWidth.txt` を取得するか、引数で渡したローカルファイルを読む。ビルドからは呼ばない。失敗したら終了コード 1 で、表は残さない。生成のあと `docs/unicode-version.md` を `18.0.0` に更新する。
2. 分類表は、コードポイントの区間の列にする。全コードポイントの配列にはしない。コンパイル時間のためである。一般カテゴリと、東アジア幅が W または F であることの 2 種類を出す。幅のそれ以外は記録しない。仕様は W と F だけを幅 2 とするためである。
3. ASCII の文字種は Unicode カテゴリで決めず、ISO 6.5 の表をコードに書く。非 ASCII だけ生成表を使う。`!` や `;` が Po であるために図形トークンになる、という取り違えを避けるためである。
4. 非 ASCII の図形文字は `Sm`、`So`、`Pd`、`Po` である。アトムの先頭になれるのは `Ll`、`Lo`、`Lm`、`Nl` と、ASCII の `a-z` である。変数の先頭は ASCII の `A-Z` と `_`、および `Lu`、`Lt` である。`Mn` と `Mc` はアトムと変数の継続だけに使い、先頭には使えない。数字は ASCII の `0-9` だけである。下線は U+005F だけを変数の先頭にする。全角の下線は図形文字のままである。
5. レイアウトは、カテゴリ `Zs`、`Zl`、`Zp` と、U+0009、U+000A、U+000B、U+000C、U+000D、U+0085 である。ファイル先頭の U+FEFF は 1 回だけ読み飛ばす。それ以外の U+FEFF と、その他の制御文字は不正文字である。
6. バッククォートは引用でも図形でもない。不正文字として失敗させる。文字列型を持たないためである。
7. 改行は `\n`、`\r\n`、`\r` の 3 つである。`\r\n` は 1 つの改行とし、列を 1 に戻す。
8. 整数トークンの `_` は、同じ基数の数字と数字の間にだけ置ける。先頭、末尾、連続、小数点の隣、指数記号の隣は失敗である。`0b`、`0o`、`0x` の接頭辞は小文字だけである。中の桁は、16 進に限り `A-F` も認める。
9. 整数トークンの値は 0 以上である。`-42` は前置演算子 `-` と整数 `42` であり、負の整数セルではない。`int64` に収まらない整数トークンは失敗であり、浮動小数にはしない。`max_integer` は `2^63-1`、`min_integer` は `-2^63` のまま、算術の段階まで評価はしない。
10. 61bit 符号付きに収まる整数だけを即値にする。範囲は `-2^60` 以上 `2^60` 未満である。そこから外れて `int64` に収まる値はボックスにする。ファクトリは、即値に収まる値をボックスにしない。
11. ヒープの既定容量は `1 << 20` セルである。コンストラクタで一度だけ `reserve` し、再配置しない。超えたら `mosa::ResourceLimit` を投げる。この例外は `std::exception` の派生とし、構文エラーには使わない。テストは小さい容量を渡せる。アトム表に個数の上限は置かない。
12. アトム番号 0 は欠番とする。空アトム `''` は 0 以外の番号を持つ。同じ UTF-8 バイト列は同じ番号になる。正規化はしない。全バイトが 0x80 未満のアトムには ASCII フラグを立てる。フェーズ1の処理はこのフラグを読まない。`char32_t` から 1 文字アトムを作る関数はフェーズ1で用意する。
13. 演算子表のキーは UTF-8 の `std::string` とする。アトム表には依存しない。lexer と演算子表を Cell より先に置くためである。
14. 既定の演算子は 13211-1:1995 の表7だけから始める。次を入れる。`:`、`|`、`*->` は入れない。`xor` は演算子にしない。

    | 優先度 | 指定子 | 名前 |
    | --- | --- | --- |
    | 1200 | xfx | `:-` `-->` |
    | 1200 | fx | `:-` `?-` |
    | 1100 | xfy | `;` |
    | 1050 | xfy | `->` |
    | 1000 | xfy | `,` |
    | 900 | fy | `\+` |
    | 700 | xfx | `=` `\=` `==` `\==` `@<` `@=<` `@>` `@>=` `=..` `is` `=:=` `=\=` `<` `=<` `>` `>=` |
    | 500 | yfx | `+` `-` `/\` `\/` |
    | 400 | yfx | `*` `/` `//` `rem` `mod` `<<` `>>` `div` |
    | 200 | xfx | `**` |
    | 200 | xfy | `^` |
    | 200 | fy | `+` `-` `\` |

    `div` は Cor.2 の追加として入れる。実装時に Cor.2 の表7差分を確認し、`div` が表に無ければ入れず、`docs/iso-notes.md` にその条番号と「表に無いので入れなかった」とだけ書く。質問にはしない。Cor.2 がこれ以外の演算子を表7に足していれば、それも入れる。
15. `OperatorTable::define` は Prolog 項を作らず、次の拒否だけを返す。優先度が 0 未満または 1200 超。指定子が `xf` `yf` `xfx` `xfy` `yfx` `fx` `fy` 以外。`,` の変更と削除。`[]` と `{}`。同じ名前の中置と後置の併存。`|` の前置と後置。`|` の中置で優先度が 1000 以下。優先度 0 は、その名前と指定子の組だけを消す。同じ名前の別指定子は残す。`|` の優先度の条項が「1000 より大きい」でなければ、実装せず `docs/iso-notes.md` に「A: 1000 より大きい、B: 条項の値」と書いて止まる。
16. ケースの演算子宣言は、そのケースの開始時に既定表をコピーした表へ適用する。ファイルの後ろのケースからは見えない。
17. リーダの結果は、項、入力の終わり、失敗のどれか一つである。項には、最初に現れた順の変数名と、一度しか現れない名前（シングルトン）を付ける。`_` はどちらの一覧にも入れない。同じ名前は同じ REF である。`syntax.pl` の成否はシングルトンを見ない。C++ テストが見る。
18. `DoubleQuotes` はリーダの引数である。既定は `Codes`。`Codes` はコードポイントの整数リスト、`Chars` は 1 文字アトムのリスト、`Atom` は 1 つのアトムである。空文字列は、リスト 2 種では `[]`、`Atom` では `''` である。
19. 構文の失敗理由は列挙型とする。訳文は持たない。メッセージ目録は後のフェーズであるため。最低限、次を分ける。`InvalidUtf8`、`IllegalCharacter`、`UnterminatedQuote`、`BadEscape`、`IntegerOverflow`、`UnexpectedToken`、`MaxArity`、`IncompleteTerm`。列はコードポイント単位である。トークンの綴りは、失敗箇所のトークン文本である。入力の終わりでトークンが無いときは空文字列とする。
20. 引数の最大個数は 1024 である。1025 個は `MaxArity` で失敗する。
21. 終端のピリオドは、ピリオドの直後がレイアウトか入力の終わりのときだけである。それ以外のピリオドは、浮動小数点か図形トークンの一部である。
22. ブロックコメントはネストしない。`/*` と `%` の両方を lexer が捨てる。
23. 往復の一致はユニフィケーションではない。`f(A, B)` と `f(B, A)` は一致しない。名前のある変数は名前が同じときだけ対応する。名前の無い変数は、出現位置の間の一対一対応で対応づける。同じ REF が複数回現れるときは、対応先も同じ REF でなければならない。名前のある変数と `_` は対応しない。
24. ライタは、名前表にある REF をその綴りで書く。名前が無く一度だけの REF は `_` と書く。名前が無く複数回現れる REF は `_G` に十進の番号を付け、同じ REF には同じ番号を付ける。番号は書き出し中に出現した順である。
25. ライタの空白は、トークンが再び分かれるための最小限に、コンマの直後の空白 1 つを足したものである。中置の `+` などの前後には空白を置かない。前置の `-` を重ねて `--` という 1 トークンになるときは、間に空白を置く。`ignore_ops(false)` のとき、リストは `[...]`、中括弧は `{...}`、演算子は演算子表記である。`ignore_ops(true)` のとき、リストは `'.'/2`、中括弧は `'{}'/1`、演算子は関数表記である。被演算子は、ISO 6.3.4 の優先度規則に合うときだけ括弧を省く。
26. `quoted(true)` は、そのままではアトムとして読めない綴りだけを引用する。`東京` は引用しない。`東 京` は引用する。`quoted(false)` は引用符を付けない。往復の判定は `quoted(true)` だけを使う。
27. 負の整数セルを書いた形は十進の符号付きである。これを再読取りすると前置マイナスの複合項になる。往復の保証は、リーダが作った項に限る。C++ で作った負の整数の見た目は C++ テストで見る。負のゼロは `-0.0` と書く。
28. 浮動小数の出力は `std::to_chars` の最短表現を使い、小数点も指数も無いときは `.0` を足す。指数の記号は `e` である。
29. `mosatest --roundtrip <パス>` を追加する。パスは第 2 引数だけである。ファイルはバイナリで読み、パスの文字コード変換はしない。フェーズ1のテストパスは ASCII であるため。引数が無い、または形式が違うときは、標準エラーに `mosatest: 使い方: mosatest --roundtrip <ファイル>` と出して終了コード 1 とする。`--version` が引数のどれかと完全一致するときは、フェーズ0と同じく版だけを出して終了コード 0 とする。
30. 版文字列 `mosa 0.0.1 (phase 0)` は、往復が通りフェーズ1完了を STATUS に書くコミットで、`mosa 0.0.1 (phase 1)` に変える。そのコミットで 3 つの版テストの期待値も変える。それより前のコミットでは版テストを壊さない。
31. C++ テストは領域ごとに実行ファイルを分け、`tests/cpp/harness.hpp` をそのまま使う。harness は 50 行を超えて伸ばさない。
32. ヘッダは `include/mosa/` に、`cell.hpp`、`heap.hpp`、`atom.hpp`、`unify.hpp`、`operator_table.hpp`、`lexer.hpp`、`reader.hpp`、`writer.hpp`、`syntax_error.hpp` として置く。`mosa.hpp` と `runtime.hpp` の中身はフェーズ0のままである。生成コードが include する面を、このフェーズでは増やさないためである。

## Cell とヒープ

ADR 0001 のタグに、ボックス化整数のタグを 1 つ足す。これが ADR 0002 に写す決定である。

下位 3bit がタグである。ヒープ上のポインタは 8 バイト境界なので、下位 3bit は 0 である。タグはポインタに足す。

| 値 | タグ | 中身 |
| --- | --- | --- |
| 0 | `Ref` | ポインタ。未束縛の REF は自分自身の番地を持つ。タグ 0 なので、番地をそのままセルの値にできる |
| 1 | `Atom` | 32bit のアトム番号 |
| 2 | `Int` | 61bit 符号付き即値 |
| 3 | `Str` | 関数語の番地 |
| 4 | `Lis` | 先頭要素の番地。直後のセルが末尾 |
| 5 | `Float` | ペイロード 1 語の番地。ペイロードは `double` のビット列 |
| 6 | `Big` | 予約。フェーズ1では作らない |
| 7 | `IntBox` | ペイロード 1 語の番地。ペイロードは `int64` のビット列 |

`Str` の指す語は関数語であり、項ではない。下位 3bit は 0、続く 11bit がアリティ（0 以上 1024 以下）、続く 32bit がアトム番号である。引数はその後にアリティ個並ぶ。

`Float` と `IntBox` のペイロードも項ではない。ヒープを先頭から項として走査してはならない。フェーズ7の GC は、タグ付きポインタを辿る。この制約を ADR 0002 の影響に書く。

空リストはアトム `[]` である。`Lis` ではない。`{a}` は関手 `'{}'/1` である。専用タグは持たない。

トレイルは、束縛した REF の番地を積む。ユニフィケーション開始時のヒープ長より前にあるセルだけを積む。開始後に作られたセルは、失敗時にヒープ長を戻すと消えるため、積まない。フェーズ1のユニフィケーションはヒープを伸ばさない。それでも境界は取っておく。フェーズ2の選択点が同じ境界を使うためである。失敗したらトレイルを戻して束縛を外す。成功したら束縛は残る。選択点スタックは作らない。

既定のユニフィケーションは出現検査をしない。`X = f(X)` は成功する。循環項を作る構文は無い。ユニフィケーションは循環が無い前提で書き、訪問集合は持たない。浮動小数は数値として比較する。`0.0` と `-0.0` は一致する。`NaN` は `NaN` と一致しない。

`unify` は 2 つの `Cell` を受け取り、`bool` を返す。失敗のときにヒープとトレイルは呼び出し前に戻る。

## lexer とリーダ

lexer は Cell を作らない。トークンは種別、解読後のテキストまたは数値、行、列、バイト位置を持つ。アトムのテキストは、エスケープを展開した UTF-8 を所有する。入力の `string_view` は、解読が終わるまで有効であればよい。

リーダは Pratt 法で書く。優先度の正本は ISO 6.3.4 である。`read(最大優先度)` が、その優先度以下の項を読む。中置 `xfy` は右が緩く、`yfx` は左が緩い、`xfx` は両側が演算子よりきつい。前置 `fy` と `fx`、後置 `yf` と `xf` も同じ条項に従う。

コンマは優先度 1000 の演算子である。関数の引数とリストの要素は優先度 999 以下として読む。`f(a, b)` は 2 引数、`f((a, b))` はコンマ項 1 引数である。`[H|T]` の `|` は演算子ではなくリストの区切りである。`|` は 1 つだけ置ける。

`end_of_file` は、次の非レイアウトが入力の終わりのときに、項とは別の結果として返す。アトム `end_of_file` を読んだ結果とは区別する。

## syntax.pl

ハーネスは Prolog としてこのファイルを実行しない。行頭が `% case: ` である行でケースを分割する。`% expect: ` で始まる行は、ライタ出力と完全一致させる文字列であり、リーダには渡さない。それ以外の本文をリーダに渡す。

1 ケースは、0 個以上の `:- op(優先度, 指定子, 名前).` と、その後の項 1 つである。`:-` の引数が `op/3` でない指示は失敗とする。項の後に非レイアウトが残っていたら失敗とする。期待文字列が書かれているときは、ライタの出力がその文字列と一致し、かつ再読取りも一致することを求める。期待文字列には終端のピリオドを含めない。

ケース識別子はファイル内で一意である。失敗の表示に使う。

最低限のケースは次である。規格第6章の例が手元にあり、この一覧より細かいときは、例をこの形式で足す。例の文面を、実装に合わせて書き換えない。

| `quoted_space` | `'a b'.` と、期待文字列 `'a b'` |
