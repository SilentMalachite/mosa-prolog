# リリース 0.1.0 設計（マニュアル・リリースパッケージ・文書の整備）

日付: 2026-11-07
状態: 承認済み（2026-11-07）

## 意図

Mosa Prolog の最初の公開版 0.1.0 を出す。Prolog に初めて触れる人が、自分の OS 用のパッケージをダウンロードして展開し、マニュアルの例を打つと、マニュアルに書いてある通りの結果が出る。これが成功の条件である（持ち主）。

「実際に操作できること」と「マニュアル通りに動作すること」の二つが持ち主の求めるもので、後者は人の注意ではなく CI で保証する（マニュアルの例を抜き出して、パッケージの中身で実行し、出力を比べる）。

読む人は、このあと実装計画を書き、実装するエージェントである。

## 決まっていること（持ち主の決定、2026-11-07）

- 読者は Prolog そのものに初めて触れる人
- マニュアルは `docs/manual/ja/` と `docs/manual/en/` に置く
- リリースパッケージを作る（各 OS のバイナリと同梱ランタイム）
- README など各種文書もリリースに向けて整備する
- 版番号は 0.1.0（タグ名、パッケージ名、`mosa --version`、バッジのすべて）
- 例のコードは言語ごとに名前を変える。日本語版は `親(太郎, 一郎)` のように日本語の原子で、英語版は `parent(tom, bob)` のように英語で書く。両版の例に共通の番号を付け、同じ数・同じ順で揃っていることを検査で確かめる
- Windows で `LANG` が無いときは、Windows の表示言語に従ってメッセージの言語を決める（日本語なら `ja`）。`mosac` で作った実行ファイルも同じ
- コード署名なしで出す。マニュアルに Gatekeeper と SmartScreen の警告の越え方を書き、Smart App Control が有効な Windows 11 は動作対象外と明記する
- Windows のコンソールで日本語を打つ確認（STATUS の「Not run yet」の `chcp 932` / `chcp 437`）はリリース前に行わず、CHANGELOG の既知の制限に「未検証」と書いて出す

## 目標

1. マニュアル（日本語と英語、同じ章立て、例は言語ごとの名前で同じ数・同じ順）
2. マニュアルの例を検査する仕組み（ctest と CI に入る）
3. 3 OS のリリースパッケージを作る CI ワークフロー
4. リリースに向けた README・CHANGELOG ほかの整備と、版番号の 0.1.0 への更新
5. Windows の表示言語によるメッセージ言語の既定（上の決定）

## 目標でないこと

- `mosac dist`（利用者のプログラムを配布用に固める機能）。今回は作らない。マニュアルと CHANGELOG には「まだ無い」と書く（私の判断。提示して持ち主の異論なし）。そのためフェーズ 7 は 0.1.0 では閉じない（私の判断）。README の表とバッジは「フェーズ 7 進行中」のままにし、SPEC は変えない
- コード署名と公証（上の決定）
- インストーラ（.pkg、.msi、.deb）、Homebrew、winget
- Linux aarch64、macOS x86_64 のパッケージ（Linux aarch64 は STATUS で未検証）
- HTML や PDF への変換。マニュアルは Markdown のまま（GitHub で読め、パッケージにもそのまま入れる）
- 言語機能や組み込み述語の追加。例外は上の Windows の表示言語の件だけ。マニュアルを書く途中で見つけた不具合は、直すなら別の作業として切り出す

## やってはいけないこと（できても失敗とみなすもの）

- マニュアルに、書いてある通りに動かない例が残る
- 検査できない例を黙って検査から外す。外すなら外す印をマニュアルの中に明示し、数を最小にする
- パッケージを展開しただけでは `mosa` が動かない（ビルドや追加のインストールが要る）。`mosac` が C++ コンパイラを要るのは仕様どおりで、これは除く
- ない機能（`mosac dist` など）を使えるように書く
- 「SWI-Prolog ではこう」を基準に説明する。説明の基準は ISO と Mosa の実際の動作
- 日本語版と英語版の内容がずれる（章、節、例の数と順、説明の範囲）

## 制約

- AGENTS.md の規則に従う。特に: 新しい依存を足さない（Python なども CI やビルドの必須にしない）、文書は英語版が正で日本語版を同じコミットで直す、STATUS.md は 15 行以内、コミットは論理単位ごとに日本語 1 行、3 OS の CI が緑
- マニュアルは `docs/manual/en/*.md` が正、`docs/manual/ja/*.md` がその翻訳。ファイル名と章立ては両方で同じ。例の名前だけが言語ごとに違う
- コードを書く部分（例の検査器、Windows の表示言語）は関数 60 行・ファイル 800 行の制限、警告はエラー、OS 依存は `src/platform/` だけ
- タグの push と GitHub Release の公開は持ち主が行う。ワークフローは下書き（draft）の Release を作るところまで（私の判断）

## 動作環境（私の判断）

- macOS 14 以降（Apple Silicon）。リリース用のビルドは `CMAKE_OSX_DEPLOYMENT_TARGET=14.0` で作り、`mosa` も同梱の `libmosa` と翻訳済みライブラリも同じ値にする。コードは浮動小数点の `std::to_chars` を使うので 13.3 より下にはできない。利用者の機械の `mosac build` は、その機械の既定の対象で作ってよい（古い対象のライブラリを新しい対象の実行ファイルに結ぶのは問題ない）。リンカが対象の違いを警告しないか、実装時に確かめる
- Linux x86_64 は Ubuntu 24.04 で作り、「Ubuntu 24.04 以降と同等の glibc」と書く
- Windows 10（22H2）以降と Windows 11 の x64。Smart App Control が有効な機械は対象外

## Windows の表示言語

- 今の既定は `LANG` だけを見る（`src/machine/messages.cpp` の `default_message_language`、ADR 0007、SPEC 第 7 節 314 行）。Windows は `LANG` を設定しないので、日本語の Windows でもエラー文が英語になる
- `LANG` があればこれまでどおり `LANG` で決める。`LANG` が無く Windows の表示言語が日本語なら `ja`、それ以外は `en`。表示言語を読むのは `src/platform/` の関数にする（Windows 以外では「わからない」を返し、今の動作のまま）
- ADR 0007 に追補を書き、SPEC 第 7 節（英語版と日本語版）の `message_language` の既定の記述を直す。持ち主がこの案を選んだこと（2026-11-07）を承認として ADR の状態に書く
- テストは、表示言語を読む関数を差し替えられる形にして、`LANG` の有無と表示言語の組み合わせを確かめる

## マニュアル

### 章立て（私の判断。順序は変えてよい）

1. はじめに: Mosa Prolog とは何か、このマニュアルの読み方
2. 入手と起動: OS ごとの展開、PATH の通し方、`mosa --version`、macOS の隔離属性と Windows SmartScreen の警告の越え方、Smart App Control が有効な機械では動かないこと、終了の仕方
3. 最初の問い合わせ: `?-` で問う、答えと `;`、`true.` と `false.`
4. 事実と規則: ファイルに書いて読み込む（`consult/1` と `mosa file.pl`）、変数、バックトラック
5. 項と単一化: 原子、数、複合項、`=`、`==`
6. 算術: `is/2`、比較、整数と浮動小数点
7. リストと再帰: `[H|T]`、自分で再帰を書く、`length/2` などの組み込み
8. 制御: `,` `;` `->` `\+`、カット `!`
9. エラーと例外: エラー表示の読み方、`catch/3` と `throw/1`
10. 入出力: `write/1`、`read/1`、ファイル
11. 日本語で書く: 日本語の原子、`_太郎` 形式の変数、字数は Unicode スカラー値で数えること、NFC/NFD を正規化しないので見た目が同じでも別の原子になりうること（SPEC 第 4 節がマニュアルに明記を求める）、全角記号モード、エラー文の言語（`LANG` と Windows の表示言語で決まり、`message_language` フラグで変えられる）
12. モジュールとライブラリ: `use_module`、`library(lists)` の `append/3` ほか、`format/2`
13. 実行ファイルを作る（`mosac`）: C++ コンパイラの入れ方（Xcode Command Line Tools、`apt install g++`、Visual Studio Build Tools）、`mosac build`、`mosac run`、`initialization(main, main)`、`mosac toolchain`。`mosac dist` はまだ無いこと
14. 参考: `mosa` のコマンド行、フラグ、環境変数（`MOSA_HEAP_MAX` ほか）、組み込み述語とライブラリ述語の一覧、ISO との違いと既知の制限

チュートリアル部（3〜12）は、前の章までに出たことだけで読めるようにする。`use_module` が要る述語（`append/3`、`format/2` など）は、第 12 章より前で使うならその場で `use_module` を説明するか、章の順を入れ替える（実装者が決める）。

### 例の書き方と検査

- 読者に打たせる例はすべて、期待する出力をマニュアルに書く
- 例は抜き出して実行し、出力が一字でも違えば失敗にする。日本語版と英語版の両方を検査する
- 両版の例には共通の番号（印）を付け、検査器は両版で番号の集合と順が同じことも確かめる。名前は言語ごとに違ってよい
- 検査はリリースパッケージを展開したもの（インストールした配置）に対して行う。ビルドツリーではなく、利用者が受け取るもので確かめるため（私の判断）。CI の通常のジョブではビルドツリー、またはその場で `cmake --install` した配置でもよい
- REPL のやりとり（`?- ` と答え、`;`）は、利用者が端末で見るものと同じ表示を検査する。端末でない入力では `mosa` は REPL に入らない（`src/main_mosa.cpp` は `standard_input_is_terminal()` で分ける）ので、検査器は REPL と同じ経路（`run_session` に `tty = true` を渡すなど）を通す必要がある。Windows のコンソール（UTF-16 の入力経路）は通らないので、その経路は上の決定どおり未検証として扱う
- エラー文はメッセージの言語で日本語か英語になる。日本語版の例は日本語、英語版の例は英語で検査する
- 組み込み述語とライブラリ述語の一覧は、実際の処理系と両方向で突き合わせる（一覧にあって無いもの、有って一覧に無いもの、のどちらも失敗）（私の判断）
- 検査できない例（インストール手順、OS 固有の操作、C++ コンパイラの無い環境での `mosac`）には、検査から外す印をマニュアルの中に付ける。印の書き方は実装者が決める（Markdown で表示されない形にする）
- `mosac` の章の例は、C++ コンパイラのある CI ジョブでは検査する

## リリースパッケージ

- 対象: macOS arm64（`.tar.gz`）、Linux x86_64（`.tar.gz`）、Windows x64（`.zip`）
- 名前の例: `mosa-0.1.0-macos-arm64.tar.gz`（形は実装者が決めてよい）
- 中身: `bin/` に `mosa`・`mosac`・`mosatest` と `bin/lib/*.pl`、`lib/mosa/<key>/` に同梱ランタイム（`libmosa`、ヘッダ、翻訳済みライブラリ）、`lib/mosa/source/`（`--runtime-source` 用）、LICENSE・NOTICE・README・CHANGELOG、マニュアル。配置は今の `install()` の規則（`CMakeLists.txt` 218〜224 行）と SPEC 第 6 節に合わせる
- 作り方: `cmake --install` した配置を CMake 同梱の道具（CPack か `cmake -E tar`）で固める。新しい依存は足さない
- ワークフロー: `v*` のタグの push で 3 OS でビルド・テストし、パッケージを作り、展開してマニュアルの例を検査し、通ったものを下書きの GitHub Release に添付する。手動実行（`workflow_dispatch`）ではパッケージを Actions の成果物に置くだけにする
- `mosac` は利用者の機械の既定の C++ コンパイラで動くこと。マニュアルが入れ方を書くコンパイラ（macOS は Apple Clang、Linux は `g++`、Windows は MSVC）に合う同梱ランタイムを必ず入れる。Linux で clang 用も入れるかは実装者が決める

## 文書の整備

- `README.md` / `README.ja.md`: 冒頭を利用者向けにする（何か、ダウンロードと最初の起動、マニュアルへのリンク）。ソースからのビルド手順は開発者向けの節として残し、フェーズ 7 の完了条件「README の手順だけで初見の人がビルドできる」を満たす。古い記述を直す（Status 節の「GC は phase7-gc ブランチで完了」、Phase バッジ `6_done` はフェーズ 7 進行中に、Version バッジは 0.1.0 に）
- `CHANGELOG.md` / `CHANGELOG.ja.md` を新設し、0.1.0 の内容（できること、動作環境、既知の制限、ISO との違い、`mosac dist` はまだ無いこと、Windows コンソールでの日本語入力は未検証であること）を書く。既知の制限は STATUS.md の Open から利用者に関係するものを選ぶ
- `docs/manual/{en,ja}/README.md` を目次にする
- README の文書一覧にマニュアルと CHANGELOG を加える
- 版番号: `CMakeLists.txt` の `project(mosa VERSION …)` を 0.1.0 にし、`mosa --version` は `mosa 0.1.0` にする（`(phase N)` は外す。私の判断）。`mosac --version`、`mosatest --version` も同様。版番号を表示や比較に使っている箇所（テスト、CI、バッジ）を合わせる
- `docs/STATUS.md` はいつもどおり更新する
