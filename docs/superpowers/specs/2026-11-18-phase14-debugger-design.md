## 目標

- `mosa` の REPL、`-g` のゴール、`initialization/1,2` のゴールで、5 つのポート（呼出・成功・再試行・失敗・例外）を持つトレースができる。
- `spy/1` でスパイポイントを置き、そこまで普段に近い速さで走らせ（leap）、そこから細かく追える。
- ポートで止まったとき、行単位のコマンドで、creep、skip、leap、fail、retry、abort、nodebug、呼び出しの並びの表示、ゴールの全体の表示、スパイポイントの付け外し、ヘルプができる。
- ポート名、ヘルプ、知らせの文面は、OS の表示言語に合わせて日本語か英語になる（ADR 0007 の仕組み）。
- `mosac build` の実行ファイルの中でも、デバッガの述語は `mosa` と同じく状態を変え、同じ結果を返す。ポートは出さない（決定 A）。
- デバッグを切っている間の `mosa` の速さは、0.4.1 から落ちない。

## 非目標

- 生成コード（`mosac` の実行ファイル）の中でのポートの表示（決定 A）。`mosac build --debug` の節の追跡は変えない。
- 1 文字で反応する入力（端末の生モード）。コマンドは 1 行ずつ読む。
- ライブラリの述語の中に入ること。ライブラリの述語は 1 つの箱として見せる。
- 条件付きのスパイポイント、ウォッチポイント、`visible/1`、`trace/1,2`（ポートを止めずに書くだけの追跡）、`abort/0` の述語、`portray/1` を使った表示、GUI と IDE との統合。
- 変数の名前を行をまたいで揃えること（「既知の制限」）。
- retry で、副作用（`assertz/1`、入出力）を元に戻すこと。
- トレース中の末尾呼び出しを、普段と同じ大きさのメモリで回すこと。
- このフェーズでの公開。公開は所有者の依頼で別に行う。

## アンチ目標（技術的に動いても、これをやったら失敗）

- デバッグを切っている間に、答え、出力、例外、速さのどれかが変わること。
- デバッグ中に、プログラムの答えが変わること。カット、`catch/3`、`findall/3`、`\+`、`->`、`*->`、`setup_call_cleanup/3`、`call/N` の意味は、トレースしていてもいなくても同じでなければならない。例外は利用者の `f`、`r`、`a` のコマンドで、これは利用者が意図して結果を変える。
- デバッグ中に、トップレベルの答えの後に、無いはずの選択点が残ること（決定的な問い合わせで `;` を問うこと）。
- `mosatest --diff` の差分が出ること。ポートを比べるテストを `tests/pl` に置いて差分を出すことも含む。
- ISO 列の分母を変えること。
- テストの期待値を実装に合わせて書き換えること。

## 制約

- AGENTS.md のとおり。
  - C++20 標準ライブラリと CMake だけを使う。
  - 関数は 60 行以内、ファイルは 800 行以内にする。
  - 生の `new`/`delete`、`reinterpret_cast`、C 配列、マクロを使わない。
  - エラーは `throw_error`/`make_*_error` の族と、今の `formal_*` の助け手だけで作る。アトムの名前を文字列で直に書かない。
  - OS に依る書き方は `src/platform/` の外に書かない。
  - 識別子は英語で書く。コメントとコミットメッセージは日本語で書く。文書は英語が正で、`*.ja.md` を同じコミットで直す。
- 選択点の種類（`Pick`）と制御の枠の種類（`Ctrl`）を足すのは、実行の形を変える。AGENTS.md の規則どおり、実装の前に ADR 0028 を書く。IR（`IrTag`）は変えない。所有者が設計を承認して実装を頼めば、それを ADR の承認とみなす（これまでのフェーズと同じ扱い）。ADR の Status にそう書く。
- `src/machine/internal.hpp`（794 行）と `src/builtins/write_pred.cpp`（799 行）には足さない。足す前に、振る舞いを変えずに分ける。デバッガの本体は新しいファイルに置く。`engine.cpp`、`choice.cpp`、`catch.cpp` には、箱へ渡す短い呼び出しだけを足す。
- テストを先に書く（TDD）。デバッガの述語は ISO の述語ではないので、規格の Examples は無い。

## 作り方の候補（所有者が 1 を選んだ）

1. **エンジンに箱を作る（選んだ案）。** デバッグ中だけ、見せる呼び出しのたびに、番兵の選択点（新しい `Pick`）と出口の印の枠（新しい `Ctrl`）を積む。`catch/3` と同じ形である。
   - 利点: デバッグを切っている間の負担は、`step` の分岐 1 つだけである。leap 中はスパイポイントの述語にだけ箱を作るので、大きなプログラムでも普段に近い速さで走る。カットなどの意味は、エンジンがそのまま守る。
   - 欠点: 実行の形が変わるので ADR が要る。GC、カット、例外との絡みを試験する必要がある。
2. **Prolog で書いたメタインタプリタ（`lib/debugger.pl`）。** エンジンに手を入れない。
   - 退けた理由: カット、`catch/3`、`findall/3`、`call/N`、モジュールの文脈を書き直すことになり、意味がずれやすい。トレース中は全体が何十倍も遅くなり、大きなプログラムに使えない。
3. **読み込むときに節を書き換えてポートを差し込む。**
   - 退けた理由: トレースを入れたり切ったりするたびに述語を作り直すことになる。`clause/2` の結果が利用者に見える形で変わり、カットの効き方も崩れる。

## 決めたこと

### 利用者から見える振る舞い（所有者が承認した案。細部は私の判断）

デバッガの状態は、次の 3 つである。

- デバッグの切り替え: 入り（debug）か切り（nodebug）か。旗 `debug` の値と同じ物である。`set_prolog_flag(debug, on)` は `debug/0` と、`off` は `nodebug/0` と同じ働きをする。
- 進み方: creep（すべての見せるポートで止まる）、skip（ある箱のポートまで止まらない）、leap（スパイポイントの述語のポートまで止まらない）。デバッグが入りのときだけ意味を持つ。
- スパイポイントの組と、止まるポートの組（leash）。

述語は `system` に置く（私の判断）。学ぶ人が、何も読み込まずにプロンプトで `trace.` と打てるようにするためである。SPEC 第5節の決まりどおり、利用者が同じ名前の述語を定義すると `permission_error(modify, static_procedure, PI)` で読み込みが止まる（`print/1` と同じで、SWI-Prolog も同じ）。2026-11-18 に、`tests`、`lib`、`bench`、`docs/manual` に該当する節は無いことを確かめた。この変化は CHANGELOG の互換性の項に書く。

| 述語 | 働き |
| --- | --- |
| `trace/0` | デバッグを入れ、進み方を creep にする。次の見せる呼び出しから止まる |
| `notrace/0` | 進み方を leap にする。デバッグは入りのまま |
| `debug/0` | デバッグを入れ、進み方を leap にする |
| `nodebug/0` | デバッグを切る。スパイポイントは残す |
| `spy(+Spec)` | スパイポイントを置き、デバッグを入れる（進み方は変えない）。`Spec` は `Name`、`Name/Arity`、`M:Name/Arity`、そのリスト。`Name` だけなら、文脈のモジュールから見えるその名前の述語すべて。見つからなければ知らせを書いて成功する。`Name/Arity` は、定義の前でも置ける |
| `nospy(+Spec)` | 同じ `Spec` のスパイポイントを外す |
| `nospyall/0` | スパイポイントをすべて外す |
| `leash(+Ports)` | 止まるポートを決める。`Ports` は、ポート名（`call`、`exit`、`redo`、`fail`、`exception`）、`+Port`、`-Port`、`all`、`none`、それらのリスト。既定は 5 つすべて |
| `debugging/0` | デバッグの状態、進み方、スパイポイント、止まるポートを `user_error` に書く |

- 引数の誤りは、変数なら `instantiation_error`、形が違えば `type_error` か `domain_error` にする。Formal の名前は実装者に任せる（`throw_error` の族を使う）。どの誤りも、テストで Formal を確かめる。
- これらの述語自身、制御構文（`,`、`;`、`->`、`*->`、`!`、`catch/3` など `launch` が扱う物）、名前が `$` で始まる述語は、ポートを持たない。

**見せる呼び出しと深さ**

- 見せる呼び出しは、文脈のモジュールがライブラリのモジュールでない呼び出しである。組込と利用者の述語は、どちらも 1 つの箱になる。組込の中には入らない。
- ライブラリのモジュールの中から出る呼び出しは見せない。こうすると、`lists:append/3` は 1 つの箱になり、その中の再帰は見えない。一方、`maplist(foo, L)` が `user` の文脈で呼ぶ `foo/1` は見える（私の判断）。
- ライブラリのモジュールとは、`library(Name)` を解決して読んだモジュールである。`Module` に印を足す（`mosa` の `lib/` からでも、実行ファイルの同梱からでも同じ印）。
- 深さは、その箱を含めて、今開いている箱の数である（抜けていない箱の数）。leap 中は、スパイポイントの述語にしか箱を作らない。そのため、leap で着いた所の深さと呼び出しの並びは、開いた箱だけを数える（「既知の制限」）。

**ポートの行**

- 1 行は、ポート名、深さ、ゴールの順に並べる。例: ` 呼出: (3) append([1],[2],_G1) ?`。英語では ` Call: (3) append([1],[2],_G1) ?`。止まるポートでは行の終わりに ` ?` を付けて 1 行読み、止まらないポートでは付けずに次へ進む。字面と桁揃えはメッセージの表（`lib/messages_ja.pl`、`lib/messages_en.pl`）に置く。
- ポート名は、日本語で呼出・成功・再試行・失敗・例外、英語で Call・Exit・Redo・Fail・Exception。例外のポートでは、ゴールの後ろに投げられた項も書く。
- ゴールは `writeq` と同じ選択肢（`quoted(true)`、`numbervars(true)`）に深さ 10 の切り詰めを足して書く。変数は書き出しの今の決まりどおり `_G1`、`_G2` と行ごとに番号を振る（私の判断。テストの出力が決まった形になる）。`portray/1` は呼ばない。ポートの中で利用者のゴールを動かさないためである。
- 行は、現在の出力ではなく `user_error` に書く。`with_output_to/2` の中でも、プログラムの出力に混ざらない。

**コマンド**（ポートで止まったときに 1 行読む。行の最初の空白でない文字で決める。文字は SWI-Prolog に合わせる。私の判断）

| 入力 | 働き |
| --- | --- |
| 空の行、`c` | creep。次の見せるポートで止まる |
| `s` | skip。呼出か再試行のポートでは、その箱の次のポートまで止まらない。ほかのポートでは creep と同じ |
| `l` | leap。次のスパイポイントの述語のポートまで止まらない |
| `f` | fail。その箱を失敗させる（失敗のポートが出る） |
| `r` | retry。その箱の呼出のポートまで戻る。束縛は戻し、副作用は戻さない |
| `a` | abort。問い合わせを止める。REPL ではプロンプトに戻る |
| `n` | nodebug。デバッグを切って続ける |
| `g` | 今開いている箱の並びを、内側から深さ付きで書き、もう一度問う |
| `w` | ゴールを深さを切らずに書き、もう一度問う |
| `+`、`-` | その箱の述語にスパイポイントを置く、外す。もう一度問う |
| `h`、`?` | コマンドの一覧を書き、もう一度問う |
| ほか | 知らない入力だと知らせ、`h` を勧めて、もう一度問う |

- コマンドは、REPL が答えの後の `;` を読むのと同じ所から読む（`Cursor`）。端末でも、`MOSA_TRANSCRIPT=1` でも、`run_session` の `input` の文字列でも同じに動く。セッションは機械にコマンドの行を読む口を渡す。
- 端末でコマンドを読んでいて入力の終わり（EOF、Ctrl-D）に着いたら、`n` と同じに扱う。
- 標準入力が端末でない `mosa`（`MOSA_TRANSCRIPT=1` が無いとき）は、コマンドを読まない。標準入力は `user_input` のもので、先に読まない今の方針を変えないためである。このとき、すべてのポートを止めないポートとして扱い、行を書くだけで進む。進み方は変わらないので、leap ならスパイポイントの述語のポートだけが書かれる。`mosa file.pl -g 'trace, main' -t halt 2> trace.log` で、トレースを記録として残せる（私の判断）。
- abort は、トップレベルに戻る止まり方を新しく作る。`catch/3` では捕まえられない。`setup_call_cleanup/3` の後始末を動かすかどうかは `halt` に揃える。知らせ（たとえば「% 中断しました」）を 1 度だけ書く。abort の後も、デバッグの状態は変えない。どこで abort したかで、次のように終わる（私の判断）。
  - REPL の問い合わせ: プロンプトに戻る。
  - `-g` のゴール: そのゴールが失敗したのと同じに扱う。今の `-g` の決まりどおり、対話なら次の `-g` とプロンプトへ進み、一括なら失敗の終了コードで終わる（`session.cpp` 451〜460 行目）。
  - `initialization(main, main)` の入口: 入口が失敗したのと同じに終わる。
  - 読み込みの中（指令、`initialization/1` のゴール。起動時のファイルでも、問い合わせの中の `consult/1` でも）: その読み込みを、読み込みの誤りと同じく失敗させて元に戻す（2026-10-29 の所有者の決定 A。iso-notes「7.4.2 Other directives」）。そのうえで、外側の問い合わせ（起動時なら読み込み全体）を止める。起動時のファイルなら、今の読み込みの失敗と同じ道で終わる。
- デバッグが入りのとき、REPL のプロンプトは `[trace] ?- `（creep）か `[debug] ?- `（leap と skip）にする（私の判断。今どの状態かを学ぶ人に見せる）。

**ポートを出す所**

- ポートを出すのは、`mosa` のコマンド（`run_session` を通るセッション）だけである。セッションは、機械にデバッガの口（ポートの行を書き、コマンドの行を読む物。端末でなければ読まない）を渡す。口があるときだけ、デバッグ中の `step` が箱を作る。
- `mosatest`、`mosac build` の実行ファイル、埋め込みの `Machine` は口を渡さない。そこではデバッガの述語が状態を変えるだけで、箱を作らず、答えも出力も変わらない。だから `tests/pl` の行は `mosatest --diff` で両側が同じになる。

### `mosac`（決定 A）

- デバッガの述語は `libmosa` の組込なので、実行ファイルの中にもある。状態の変化と `debugging/0` の出力は `mosa` と同じになる。
- 実行ファイルは、コマンドの行を読む口を渡さない。ポートは出ない。
- `mosac build --debug` の節の追跡（`kTrace`）は変えない。2 つは別の物である。マニュアル第13章にそう書く。

### エンジンの箱（ADR 0028）

`step` で、読んだゴールを見せると決めたら、次のことをする。デバッグが切りなら、またはデバッガの口が無ければ、分岐 1 つで今と同じ道を通る。

1. 番兵の選択点 `Pick::DebugBox` を積む。中身は、元のゴール枠の番地、ヒープ・トレイル・extras の水位、箱の番号、「抜けた」の印である。
2. 出口の印の枠 `Ctrl::DebugExit` を積む。中身は元の継続（元の枠の語 3）と番兵の位置である。
3. 元の枠の写しをヒープに作り、写しの語 3 を `DebugExit` の枠にする。継続は枠の語 3 から読み直される所がある（意図の節）ので、`Goal` の値を差し替えるだけでは足りない。元の枠は書き換えない。`repeat` と `\+` が同じ枠をもう一度動かすときに、古い印を指さないためである。
4. 呼出のポートを出し、`ip` を写しにして、写しを今と同じ道（`run_builtin` か `enter_user`）で動かす。`step` が写しにもう一度箱を作らないよう、写しには箱を作らない印を付ける（形は実装者に任せる）。節のやり直しと非決定的な組込のやり直しは写しを読み直すので、どれも `DebugExit` へ抜ける。

その後は次のように動く。

- 成功（Exit）: `DebugExit` の枠に着いたら、成功のポートを出す。番兵が一番上なら（中に選択点が無い）、番兵を外して元の継続へ進む。中に選択点があれば、番兵に「抜けた」の印を付け、その上に再試行の印の選択点 `Pick::DebugRedo` を積んで進む。
- 再試行（Redo）: バックトラックが `DebugRedo` を外したら、再試行のポートを出し、番兵の「抜けた」の印を消して、バックトラックを続ける。
- 失敗（Fail）: バックトラックが番兵に着いたら、失敗のポートを出して番兵を外し、バックトラックを続ける。
- 例外（Exception）: `propagate_throw` が「抜けた」の印の無い番兵を外すときに、例外のポートを出す。印のある番兵と `DebugRedo` は、黙って外す。
- retry: 番兵より上を、カットと同じ道で切り詰める（後始末も同じに動く）。番兵の水位まで状態を戻し、元のゴール枠からもう一度箱を開く。
- fail: 番兵より上を、カットと同じ道で切り詰めてから失敗させる。番兵に着いて、失敗のポートが出る。
- skip: 対象の箱の番号を覚え、その箱のポートまでポートを出さず、新しい箱も作らない。
- leap: スパイポイントの述語の呼び出しにだけ箱を作る。スパイポイントは `Predicate` の印で引き、述語ごとに表を探さない。組込のスパイポイントは別の小さな組で持つ。

ほかの決め事は次のとおり。

- 番兵がカットや `\+`、`->`、`once/1` の確定で外れれば、その箱からはもうポートは出ない。答えは今と同じである。
- 開いている箱の並び（`g` と深さ）は、今の選択点のスタックの中の「抜けた」の印の無い番兵を、下から順に数えた物である。指令と初期化のゴールはスタックを入れ替えて脇で動くので、その中では、その指令の中で開いた箱だけを数える（「既知の制限」）。
- `has_more` は新しい `Pick` を数えない。番兵と `DebugRedo` があっても、`;` を問うかどうかは今と同じに決まる。
- ポートの名前、ヘルプ、知らせの文面は、問い合わせの途中で引く。`render_message` は動いている問い合わせを捨てるので使わない。`message_text` を使い、ポートの名前はデバッグを入れたときに 1 度だけ引いて覚える（`gc.cpp` 143 行目の前例）。
- GC は、新しい選択点と枠の中の番地（ゴール枠、継続）を、今の `Entry` と `Extra` と同じく根として辿り、付け替える。

### テスト

- **ポートの出力**: 問い合わせとコマンドを流し、ポートの行を期待するトランスクリプトと比べるテストを `tests/cpp/` か ctest に書く。`tests/pl` には置かない（差分テストに入り、決定 A で両側が違うため）。日本語と英語の両方の文面で確かめる。日本語の名前の述語と原子のトランスクリプトもここに置く。
  - ポートの行は `user_error` に出る。`user_error` は `std::cerr` へ直接書くので、`SessionResult.err` には入らない。テストは、`std::cerr` の `rdbuf` を差し替えて `run_session(args, input, true)` を動かすか、`MOSA_TRANSCRIPT=1` で `mosa` を子プロセスとして動かして（`tests/cpp/transcript_test.cmake` とマニュアルの検査の前例）、出力を比べる。どちらにするかは実装者に任せる。
  - 番兵の外し忘れは `;` の問いでは見つからない（`has_more` は新しい `Pick` を数えない）。決定的な問い合わせをトレースした後の `Machine::choice_depth()` が、トレースしない場合と同じであることを C++ のテストで確かめる。
  - 端末でない `mosa` が、コマンドを読まずにポートの行を書くだけで進むことも確かめる。
- **状態の述語**: `tests/pl/debugger.pl`（名前は実装者に任せる）に、デバッガの述語の成功、状態、誤りの行を置く。これは `mosatest --diff` に入り、両側が同じになる。`tests/pl/japanese.pl` に、日本語の名前の述語への `spy/1`、`nospy/1` の行を足す。

## リスク

- 番兵と `DebugRedo` が、カット、`\+`、`->`、`*->`、`once/1`、`findall/3`、`setup_call_cleanup/3` の切り詰めと組み合わさる所。どの組み合わせでも答えが変わらないことを、タスク 5 と 6 のテストで、トレースした場合としない場合の答えを比べて確かめる。
- 例外のポートは `propagate_throw` のループの途中で利用者に問う。そこで retry と fail を選んだときに、巻き戻しを止めて状態を戻す道を、タスク 6 で確かめる。
- retry と fail の切り詰めで、`pending_cleanups` の後始末を動かす順（ADR 0016）。
- GC が新しい選択点と枠の番地を付け替えること。`MOSA_GC_STRESS` で確かめる。
- 決定的な成功で番兵を外し忘れても、`;` の問いには出ない（`has_more` は新しい `Pick` を数えない）。選択点が積もり、メモリが増えるだけなので見落としやすい。完了条件 1 の `choice_depth()` で確かめる。
- 指令と初期化のゴールは、選択点のスタックを入れ替えて脇で動く（`load_directive.cpp`）。トレースした `consult/1` の中の指令を追うときに、番兵が入れ替えたスタックをまたいで残らないこと、脇の実行が終わったときに開いた箱が正しく閉じることを確かめる。
- 写しの枠に箱を作らない印を付け忘れると、`step` が同じゴールに箱を作り続ける。
- `message_text` は呼ぶたびに別の機械を作るので重い。ポートの名前を 1 度だけ引いて覚えないと、トレースが遅くなる。
- 旗 `debug` を `on` にすると、今は何も起きない。このフェーズの後は `mosa` のセッションでデバッグが入る。suite と `tests/pl` は `mosatest` で動き、口が無いので箱を作らない。それでも、旗を `on` にする行の答えが変わらないことを、タスク 4 で確かめる。

## 既知の制限（CHANGELOG とマニュアルに書く）

- 変数の名前は行ごとに振るので、同じ変数でも行が違えば名前が違うことがある。
- leap で着いた所の深さと呼び出しの並びは、開いた箱だけを数える。
