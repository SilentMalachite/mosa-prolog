# Release 0.1.0 (manuals, release packages, documents) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person new to Prolog downloads the 0.1.0 package for their OS, unpacks it, types the manual's examples and gets exactly the output the manual shows, and CI proves it on the unpacked package.

**Architecture:** (1) The version becomes 0.1.0 and Windows picks the message language from its display language when `LANG` is absent. (2) `mosa` gains a test-only transcript mode (`MOSA_TRANSCRIPT=1`): piped stdin is treated as a terminal and every line taken from it is echoed, so its merged stdout/stderr equals what a terminal shows. (3) `mosatest --manual` reads `docs/manual/{en,ja}/*.md`, runs every marked example through the real `mosa`/`mosac` in transcript mode, compares byte for byte, checks the two editions carry the same example ids, and checks the predicate tables against the system. (4) Fourteen chapters per edition, written against that checker. (5) `cmake/package.cmake` turns `cmake --install` into one archive; `release.yml` builds, packages, unpacks, re-checks the manual on the unpacked tree and attaches the archives to a draft GitHub Release. (6) README, CHANGELOG and STATUS are rewritten for the release.

**Tech Stack:** C++20, CMake 3.25 (`cmake -P`, `cmake -E tar`), `tests/cpp/harness.hpp`, `mosatest`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-07-release-0.1.0-design.md` (approved 2026-11-07). Also `docs/SPEC.md` sections 4, 6, 7; ADR 0007; `AGENTS.md`.

## Global Constraints

- Version 0.1.0 everywhere: tag `v0.1.0`, package names, `mosa --version` prints exactly `mosa 0.1.0` (no `(phase N)`), `mosac --version` and `mosatest --version` the same line, flag `version_data` = `mosa(0, 1, 0, [])`, flag `version` = `100`.
- No new dependency. Python, shells other than what the runner has, and third-party actions other than `actions/checkout`, `actions/upload-artifact`, `actions/download-artifact` are not used; the release is created with the `gh` CLI preinstalled on the runners.
- Functions ≤ 60 lines, files ≤ 800 lines, no raw `new`/`delete`, C arrays, macros, `reinterpret_cast`; `-Wall -Wextra -Wpedantic` / `/W4` clean; OS-dependent code only in `src/platform/`.
- Identifiers English; code comments and commit messages Japanese, one line: `[phase7] … （リリース 0.1.0 Task N、検証）`, ending with the `Co-Authored-By` line the repository's recent commits carry.
- English is canonical: `docs/manual/en/NN-*.md` first, `docs/manual/ja/NN-*.md` (same file names) in the same commit. Example code uses English names in `en` (`parent(tom, bob)`) and Japanese names in `ja` (`親(太郎, 一郎)`); example ids are identical and in the same order.
- Explanations follow ISO and Mosa's actual behaviour, never "SWI-Prolog does X". Do not document `mosac dist` as available; it does not exist in 0.1.0.
- Do not change behaviour the manual merely describes; if a chapter exposes a bug, record it in STATUS (Open) and in CHANGELOG known limits, and keep the example out of the manual rather than fixing it inside a chapter task.
- Supported platforms written in the manual and CHANGELOG: macOS 26 or later (Apple Silicon); Linux x86_64 with glibc of Ubuntu 24.04 or later; Windows 10 22H2 or later and Windows 11, x64, with Smart App Control off. Packages are unsigned.
- Windows console Japanese input (`chcp 932` / `chcp 437`) is not verified for 0.1.0; CHANGELOG says so.
- Phase 7 stays open (`mosac dist` remains). README badge and table say phase 7 in progress; SPEC section 9 is not changed.
- Before Task 1, `docs/STATUS.md` "In progress" names this plan (AGENTS.md session start); every session ends with STATUS updated.
- After each task: `cmake --build build && ctest --test-dir build -j1` passes (serial: `suite_path_test` and `conformance_io_test` share `tests/tmp/suite`).

## Review Focus

1. Program output followed by an error in one query (`write(hello), nl, X is 1/0.`): the transcript shows `hello` before the warning, as a terminal does, even though stdout is a pipe and stderr unbuffered — `transcript_order` (Task 3).
2. A Windows checkout with `core.autocrlf=true` turns the manual into CRLF: the checker reads markers and blocks the same and compares with CR removed on both sides — `manual_parse_crlf` (Task 4).
3. The package unpacked under a path with a space and Japanese characters (`C:\Users\…\展開 先\mosa-0.1.0-windows-x86_64`): `mosa` finds `bin/lib`, `mosac` finds `lib/mosa/<key>/`, and the manual check passes there — `package_layout` unpacks into `tests/tmp/package/展開 先/` (Task 9).
4. `LANG` present but not Japanese on a Japanese Windows (`LANG=C`, `LANG=en_US.UTF-8`) keeps English; empty `LANG` falls back to the display language — `message_language_from` cases (Task 2).
5. A tag that does not match the project version (`v0.1.1` on a 0.1.0 tree) fails the release before anything is uploaded — the version step in `release.yml` (Task 10).

**Marker rules (fixed here; the chapters follow them):**
- Every fenced block in `en/*.md` and `ja/*.md` except `README.md` has, on the line right before the opening fence, one of: `<!-- check: ID -->`, `<!-- skip: ID -->`, `<!-- file: ID NAME -->`. A fence without one is a parse error.
- Multi-line input override: `<!-- check: ID` on its own line, then the input lines verbatim, then `-->` on its own line.
- `file:` blocks (language `prolog`) are written to `<work>/<edition>/<chapter-stem>/NAME` when reached; later examples of that chapter run with that directory as cwd.
- `check:` on a `text` block whose first line starts with `?- ` → `Repl`: run `mosa` with no arguments. On a `console` block → `Console`: each line starting with `$ ` is a command whose expected output is the lines up to the next `$ ` line. A command starts with `mosa`, `mosac`, `mosatest` (the binaries beside `--mosa`) or `./NAME` (a program in the chapter directory, `.exe` added on Windows); arguments split on spaces, with `'…'` and `"…"` grouping; nothing else of a shell.
- Input, unless overridden: the text after `?- ` of each expected line that starts with `?- `, each followed by `\n`.
- Every run uses `environment_with({{"LANG", en→"en_US.UTF-8" / ja→"ja_JP.UTF-8"}, {"MOSA_TRANSCRIPT", "1"}}, {"MOSA_LIB", "MOSA_HEAP_MAX", "MOSA_GC_STRESS"})`, stdout and stderr merged. Actual output is compared after removing `\r` from both sides and removing the final prompt left waiting at end of input (exactly what Task 3 pinned).
