## 方針

1. **振り分けは赤いテストで行う。** 報告の「実機確認済み」はそのまま受け取らない（前回は 165 件中 19 件が誤りか再現しなかった）。再現の手順がある物はそれをテストにし、`701dff6e` で落ちなければ「再現しない」と書いてコードは変えない。「コード確認」だけの物は、落ちる入力を自分で作る。作れなければ Note にする。
2. **測る道具を先に直す（V1）。** R-H01 と R-M12 は if-then-else と選言の試験の判定を変えるので、直すたびに `mosatest --suite` と `--diff` を流し、率が動いたら試験ごとに記録する（直すか iso-notes に書く）。率を戻すために調整しない。
3. **1 件 = 1 コミット = 直す前に赤いテスト 1 つ以上。** 既存の期待値は変えない。赤いテストが作れない物（R-L12、文書、CI の正規表現）は、生成コードや一覧が変わらないことで確かめる。
4. **振る舞いを選ぶ物は問いにする。** R-M09、R-L05、R-N03、R-M14 の「整形した JSON を拒む」部分は、受け付ける物が変わるので既定の A で A か B かの問いにし、黙って直さない。R-M20 (1)（ADR 0019 の「承認」と L-06 の問い）も持ち主の問い。
5. **ADR が要る物:** R-M01 の上限への計上は ADR 0029 と ADR 0010 の改訂 4 を変えるので、改訂を先に書く。重複を除く部分はそのまま直す。
6. **push は頼まれたときだけ。** R-M18 は ASan の時間制限が問いなので CI でしか確かめられない。まとめて push のときに見る。
