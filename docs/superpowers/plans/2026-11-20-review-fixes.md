## 方針

1. **測る道具を先に直す（W1）。** 判定器や ctest の終了コードが偽合格を出すなら、その後の修正の「テストが落ちる→通る」も信用できない。H-33 では `writer_golden_test` が 4864 件の失敗で 0 を返した。
2. **1 件 = 1 コミット = テスト 1 つ以上。** テストは古い実装で落ちることを確かめてから直す。再現しない物と設計どおりの物は、レビュー文書の状態がその記録になる。
3. **期待値は変えない。** 判定器を直して ISO 欄 2291/2326 や library 欄 600/605 が下がったら、1 件ずつ直すか、iso-notes に「規格の読みの違い」として書く。
4. **作業はブランチ `fix/review-2026-11-20` で行う。** push と PR は持ち主が頼んだときだけ。
