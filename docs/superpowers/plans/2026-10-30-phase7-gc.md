# フェーズ7 GC 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ヒープを予約したアドレス空間の上で自動で伸ばし、安全点で mark-and-compact の GC を走らせ、`loop(N)` と `tak(18,12,6)` を小さい上限でも完走させる。

**Architecture:** ヒープは起動時に上限までのアドレス空間を予約し（`src/platform/`）、確保を足して伸ばす。アドレスは動かない。GC は `run_loop` のステップの間（安全点）でだけ走る。手順は、ルートから印を付ける → 印のビット表の順位（rank）で新しい位置を決める → 1 回の走査で順序を保ってずらす、である。ヒープ・`extras`・trail の 3 つを同じ順位の考え方で詰める。入れ子の `run_loop` を回す C++ のコードは、握っている値を `RootScope` で GC に知らせる。

**Tech Stack:** C++20 標準ライブラリ、CMake 3.25+、POSIX `mmap`/`mprotect`、Windows `VirtualAlloc`（`src/platform/` だけ）。

**Spec:** `docs/superpowers/specs/2026-10-30-phase7-gc-design.md`（承認済み 2026-10-30）

## Global Constraints

- AGENTS.md に従う。関数は 60 行以下、ファイルは 800 行以下。生の `new`/`delete`、`reinterpret_cast`、C 配列、マクロは使わない。`#ifdef _WIN32` などは `src/platform/` だけに書く。警告はエラーとして扱う。新しい依存ライブラリは足さない。

- Cell の表現（ADR 0001/0002）と IR・枠の配置（ADR 0003/0009）は変えない。
- 識別子は英語、コメントとコミットメッセージは日本語で書く。コミットは 1 行で、`[phase7] 内容（確かめ方）` の形にする。
- 文書は英語が正で、`*.ja.md` を同じコミットで直す。`docs/STATUS.md` は英語だけで、15 行以下に保つ。
- 既定の上限は 4 GiB（2^29 語）。上限の決め方は「`--heap-max` → `MOSA_HEAP_MAX` → 既定」。単位は MiB の整数。API（`Machine::create` の引数）は環境変数を読まない。
- 起動時に確保する量は min(2^20 語, 上限)。
- 柔らかい容量 C の上限は `limit - headroom`。`headroom = min(max(limit / 4, 65536), limit / 2)` 語とする。GC の後で生きているデータが C の 7 割を超えたら、C を 2 倍にする（上限まで）。
- ヒープの上限に当たったら、`ResourceLimit` で今の問い合わせを止める。REPL は続け、mosac の実行ファイルは 2 で終わる。`catch/3` では捕まえられない。
- 速度の基準: `mosatest --bench` で、インタプリタ・翻訳とも、GC を入れる前より 5% 以上遅くならないこと。
- 各タスクの終わりで `cmake --build build && ctest --test-dir build` が全部通ること。

## Review Focus

1. 循環項（`X = f(X)`）が生きたまま GC されること。印付けが止まり、項が保たれることを期待する（Task 4 の `gc_cyclic`）。
2. 100 万要素を超える生きたリスト。印付けは C++ の再帰ではなく明示的なスタックで行う。スタックあふれを起こさないことを期待する（Task 4 の `gc_long_live_list`）。
3. GC の前に作った例外の項を、GC の後で `catch/3` が受け取ること。ball の値が正しいことを期待する（Task 4 の `gc_ball_survives`）。
4. REPL で最初の解の途中に GC が走ったあとの `;`。続きの解が GC が無いときと同じであることを期待する（Task 4 の `gc_redo_after_collect`）。
5. 極端に小さい上限（`Machine::create(8)` など、既存のテストが使う値）。GC の閾値の計算が壊れず、従来どおり `heap_limit` で止まることを期待する（Task 4 の `gc_tiny_limit`）。

  struct GcStats {
    std::uint64_t count = 0;
    std::uint64_t freed_words = 0;
    std::chrono::steady_clock::duration time{};
  };
  // 入れ子の run_loop を回す C++ が握る値を、GC が印付けと書き換えの 2 回に分けて訪ねる。
  class GcVisitor {
   public:
    virtual void cell(Cell& slot) = 0;
    virtual void frame(std::uint64_t& index) = 0;       // kNoFrame は飛ばす
    virtual void heap_mark(std::size_t& mark) = 0;
    virtual void trail_mark(std::size_t& mark) = 0;
    virtual void extras_mark(std::size_t& mark) = 0;
    virtual void weak_address(std::uint64_t& raw) = 0;  // 印付けでは辿らない。生きていれば新番地、死んでいれば 0

    void entry(Entry& entry);                           // Entry のセル・枠・水位をすべて訪ねる
   protected:
    ~GcVisitor() = default;
  };

    RootScope(Impl& machine, RootVisit visit);
    ~RootScope();
    RootScope(const RootScope&) = delete;
    RootScope& operator=(const RootScope&) = delete;
  };

    ~GcInhibit();

    GcInhibit& operator=(const GcInhibit&) = delete;

**決めてあるアルゴリズム（実装者が勝手に変えない部分）:**
- 印付けは明示的なスタック（`std::vector`）で行い、C++ の再帰は使わない。印は語ごとのビット表（`std::vector<std::uint64_t>`、1 ビット 1 語）に付ける。語の種類は語ごとの 2 ビットで持つ。種類は Cell・Raw・FrameIndex・ExtrasIndex の 4 つである。種類ごとの印の付け方は次のとおり。
  - 項: Str は関数語を Raw、引数を Cell とする。Lis は 2 語とも Cell とする。Float と IntBox は 1 語を Raw とする。Ref は語を Cell として、その値を辿る
  - ゴール枠: 語 0〜2 を Raw、語 3 を FrameIndex、語 4 以降の arity 語を Cell とする（arity は `goal_word_arity(語 1)` で求める）
  - 制御枠: 語 0 と 2 を Raw、語 1 を ExtrasIndex、語 3 を FrameIndex とする。印を付けた `Extra` の `env` と `cont` も辿る
  - Native 枠: 語 0〜2 と 4 を Raw、語 3 を FrameIndex、語 5 以降の count 語を Cell とする（count は語 1 の 32〜62 ビット）
  - 枠の見分け方は `step` と同じにする。語 0 が 0 なら制御枠で、さらに語 1 の第 63 ビットが立っていれば Native 枠である
- 新しい位置は `rank(i)` = i より下にある印の付いた語の数で求める。64 語の区画ごとに累計を前もって計算し、`累計 + popcount` で引く。番地は `base + rank(index) * 8 | tag`、添字は `rank(index)`、水位は `rank(mark)` になる。
- 詰め直しは、印の付いた語を下から順に 1 回だけ走査する。走査の中で、語の種類に従って中身を書き換え（Cell でポインタのタグなら番地を、FrameIndex と ExtrasIndex なら添字を書き換える）、`rank(i)` の位置へ写す。印のビット表は写しの間も変わらないので、`rank` は走査の途中でも引ける。
- `extras` は、印を付けた添字だけを順序を保って詰める（同じ rank の考え方で、別のビット表を使う）。
- trail は、印の付いた語を指す項目だけを残し、ポインタを書き換える。`trail_mark` は、残った項目のうち旧位置がその水位より下のものの数にする。
- ルートは次のものである。
  - `ip`、`ball`、`bindings` の `variable`
  - `stack` の各 `Entry`（`GcVisitor::entry` で辿る）
  - `Trail::mark`（weak_address として扱う）
  - `gc_roots` の各 `RootVisit`
  - Serena の `find_referencing_symbols` で、`Impl`・`Entry`・`Extra` の Cell 型のフィールドと枠の添字のフィールドを全部洗い出す。この一覧と食い違いがあれば、`gc.hpp` の頭のコメントに理由を書いて足す
- 方針: GC の後で `heap.size()` を生きている量 L とする。L > 0.7·C なら C を 2 倍にする（上限まで）。次の閾値は `max(C, L + (limit - L) / 2)` とする。これで、生きているデータが上限に近いときに毎回 GC が走り続けることを防ぎ、やがて確保が上限に当たって止まる。
