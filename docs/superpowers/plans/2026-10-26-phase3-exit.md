> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mosatest --suite` が Logtalk の `tests.lgt` を直接読んで分母の合格率を書き、0.9 以上になってから版を `phase 3` にする。

**Tech Stack:** C++20、CMake 3.25 以上、CTest、標準ライブラリのみ。

**Spec:** `docs/superpowers/specs/2026-10-26-phase3-exit-design.md`

- [ ] **Step 1: 失敗するテストを書く**

`tests/pl/chars.pl` に 2 件足す。ストリームは `open_string` ではなく、バイトを直接積む既存の C++ テスト `tests/cpp/stream_test.cpp` に置く。Prolog 側から壊れたバイトを書く手段は、このタスクでは足さない。

`check_invalid_utf8` の断言は次のとおり。

- 既定で、バイト `0xFF` だけの入力ストリームへの `get_char` は `representation_error(character)`。カーソルは 0 のまま

- `set_prolog_flag(invalid_utf8, error)` のあと、残りの `0xFF` は再び `representation_error(character)` でカーソルは進まない
- `set_prolog_flag(invalid_utf8, drop)` は `domain_error(flag_value, drop)`。旗は `error` のまま
- `current_prolog_flag(invalid_utf8, error)` は、置換のテストのあと旗を戻してから成功する

`tests/pl/chars.pl` には、旗の往復だけを書く。`set_prolog_flag(invalid_utf8, replace)` のあと `current_prolog_flag(invalid_utf8, replace)` が成功し、`error` に戻る。

- [ ] **Step 3: 読みと true/false/error を実装する**

`read_lgt_file` は既存のリーダで項を読む。`:- object`、`:- end_object`、`:- info`、`:- set_logtalk_flag` は捨てる。`test` 以外の節は `program` に、`write_term` したテキストとして積む。`{ゴール}` は本体のどこでも中のゴールにほどいてから積む。行頭が `-` の test は `outside` にする。

実行は、`program` を一度 `load` し、各テストの本体をクエリする。`true` は最初の成功で合格。`true(Assertion)` は最初の解で `Assertion` を実行し、失敗しても次の解は試さない。`false` と `fail` は失敗で合格。`error(Formal)` は、投げられた項が `error(Actual, _)` で、`Formal` が `Actual` を包摂するとき合格。包摂はランナーの C++ で行い、`subsumes_term/2` は登録しない。

`halt/0` と `halt/1` は `halt_now` を見て、そのテストの成功とする。プロセスは `exit` しない。次のテストの前に `halt_now` を false に戻す。クエリが機械を終了させた場合は、そのファイルの残りを不合格にし、プロセスは戻る。

読めないファイルは不合格 1 件。名前はファイルの相対パス。別欄のファイルは読まない。オブジェクトの `setup` は各テストの前、`cleanup` は成功でも失敗でも後に実行する。1 ファイルのテストは同じ機械で、ソースの順に実行する。

終了コードは `passed * 10 >= denominator * 9` のとき 0。分母 0 は 1。表示する百分率は、小数第 1 位へ四捨五入した文字列である。判定そのものはこの整数比較だけを使う。

### Task 4: 残りの結果の形

**Files:**
- Create: `src/machine/lgt_judge.cpp`
- Modify: `src/machine/lgt_file.cpp`、`src/machine/lgt_suite.hpp`、`tests/cpp/conformance_report_test.cpp`、`CMakeLists.txt`
- Test: `tests/cpp/conformance_report_test.cpp`

**Interfaces:**
- Consumes: `LgtCase`、`read_lgt_file`、タスク 3 の実行
- Produces: 設計の判定表の残りの形。`variant/2`、`subsumes_term/2`、`(=~=)/2`、`assertion/1`、`assertion/2` は、結果の形と本体の両方で C++ が判定する。利用者述語にも組込にも登録しない

- [ ] **Step 1: 失敗するテストを書く**

1 つの実行対象 `predicates/atom_length_2/tests.lgt` に、次を 1 件ずつ置く。

- `deterministic` は `p(1)` が 1 つの事実のとき合格。`p(1). p(1).` のようにやり直しが成功するときは不合格
- `errors([instantiation_error, type_error(atom,1)])` は、実際が `instantiation_error` なら合格
- `variant(S, [1+_])` は、`S = [1+_]` の別の変数名で合格。同じ変数を共有している項は不合格
- `subsumes(f(_), X)` は、`X = f(a)` で合格
- `exists(N == 2)` は、`p(1). p(2).` のとき合格
- `all(N < 3)` は、解が 1 と 2 のとき合格。解が 0 のときも合格
- `ball(oops)` は `throw(oops)` で合格
- `true(X =~= 1.0)` は、`X is 1.0` で合格。演算子はファイル内の `:- uses(lgtunit, [op(700, xfx, =~=), (=~=)/2])` のあとだけ表に入る
- 本体の `assertion(1 == 1)` は合格。`assertion(1 == 0)` はそのテストが不合格
- 同じファイルの `test(hidden, false) :- {current_predicate(variant/2)}.` は合格する。`assertion/1` と `(=~=)/2` も、このファイルの実行中に `current_predicate` の解に出ない

`(=~=)/2` の式は `abs(A-B) =< max(abs(A), abs(B)) * epsilon`。`epsilon` は評価関数 `epsilon` の値である。

- [ ] **Step 2: テストを実行して失敗を確認する**

Run: `cmake --build build && ./build/conformance_report_test`
Expected: 新しい形が不合格になる

- [ ] **Step 3: 判定を lgt_judge.cpp に置く**

`deterministic` は、最初の成功のあと `next` が失敗すれば合格とする。選択点が残っていても、やり直しが失敗すれば合格。

`variant` は、両辺をコピーし、変数を出現順に同じ番号へ置き、`==` で比べる。`numbervars/3` は呼ばない。

`uses` の `op(700, xfx, =~=)` は、そのファイルの機械の演算子表にだけ足す。ファイルが終わったら機械ごと捨てる。

このタスクで扱えない結果の形は、そのテストを不合格 1 件にする。
