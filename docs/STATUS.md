A Big step's heap check counts garbage, so it can stop at the heap limit before a safe-point GC would have freed room; evaluation copies Big operands, so reading a Big stops once it takes about half the limit and a Big result at about a third; an integer literal is parsed in full off the heap before `Heap::big` checks the limit (`lexer_literal.cpp`, Muse review), so 3,000,000 hex digits under `--heap-max 1` peaked at 23 MB RSS before the heap-limit stop (a 3,000,000-character atom peaks at 24 MB and a comment that long at 12 MB, so most of it is the reader's own memory, which is outside the limit for any long token); `'$format_radix'/4` builds the digit text off the heap before making the atom, so a Big near the heap limit in radix 2 can use about 64× its word count before the limit triggers (as `~d` does through `number_chars`); the REPL writes prompts and answers past `user_output`, so its line position stays where the query left it, and after a query whose output has no final newline the next query's leading `~N` writes an empty line (`?- format("~Nb~n").` after `?- write(a).`, seen under a pty; both are in CHANGELOG 0.2.2 Known limits). Phase 12 adds five (CHANGELOG Unreleased, Known limits): a failed goal load's diagnostic bypasses the `user_error` stream, so its column does not move; in a `mosac build` executable, `module_property(M, file(F))` gives the file's embed key resolved against the working directory (`library/Name.pl` for a bundled library, the path relative to the main file's directory for the program's own module files), which can differ from the interpreter's path; `mosac` still warns that an unqualified `maplist/3` after a goal `use_module(library(apply))` is undefined, though the executable runs (goal libraries are read as `use_module(library(N), [])`); a `M:G` into a module that no directive loads (one loaded only from a goal, or `lists` not loaded at all) goes through `:/2` at run time in a `mosac` executable; `mosac` does not bundle a file that a goal load names by a plain path, so the executable reads it from the working directory.
