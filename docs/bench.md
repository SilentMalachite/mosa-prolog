# Benchmarks

`mosatest --bench <file> [--count <N>] [--work <directory>] [--cmake <path>] [--report <file>]` runs `bench(N)` five times in the interpreter (`mosa <file> -- N`) and five times in the executable that `mosac emit` + CMake (Release) builds from the same file, then prints the wall-clock median of each side and the ratio (interpreter time divided by translated time). Each run is one whole process, from start to exit, so both sides include process start-up and the loading of the source in the same way. `N` is the same on both sides (default 20000). The emitted project, its build and the logs go under `--work` (default: `mosatest-bench` next to the `mosatest` executable, in the build tree); only the child directory `mosatest-bench-out` is removed and recreated. With `--report <file>`, the result is also written to that JSON file in the form of [`bench.json`](bench.json): one line per program, keyed by the file name as given; the line for the same file is replaced and the other lines are kept. The programs in `bench/` define `bench(N)` as a failure-driven loop, check their first solution before running it, and read `N` from the flag `argv`; `statistics/2` is not used (phase 7).

## Results

Measured on 2026-10-30 on an Apple M1 Max, macOS 27.2, Apple clang 21.0, Release build. Times are medians of five runs in milliseconds; [`bench.json`](bench.json) holds the same numbers (generated by `--report`; do not edit by hand).

| Program | N | Interpreter (ms) | Translated (ms) | Ratio |
| --- | ---: | ---: | ---: | ---: |
| nrev | 20000 | 3290 | 143 | 23.0 |
| queens | 80 | 2847 | 622 | 4.6 |
| zebra | 120 | 2810 | 1035 | 2.7 |
| tak | 100 | 2501 | 325 | 7.7 |
| deriv | 30000 | 1134 | 155 | 7.3 |
| crypt | 300 | 3073 | 327 | 9.4 |

`N` is chosen per program so that the interpreter side takes about 1–3 s and the translated side at least 0.1 s. To measure again and rewrite `bench.json`, from the repository root:

```sh
for run in nrev:20000 queens:80 zebra:120 tak:100 deriv:30000 crypt:300; do
  LANG=C build/mosatest --bench bench/${run%%:*}.pl --count ${run#*:} --work tests/tmp/bench --report docs/bench.json
done
```

The translated side is the code `mosac emit` produces as of phase 6 Task 13, unchanged for these measurements. The phase 6 exit criterion (SPEC section 9: the translated `nrev` at least 3 times faster than the interpreter) is met. The other ratios are lower than `nrev`'s; no translated code was tuned for them in phase 6.

Every program is also included by `tests/pl/bench_<name>.pl`, which runs its first-solution check and `bench(2)` as tests, so `mosatest tests/pl` checks the expected solutions and the differential test (`mosatest --diff tests/pl`, CTest `diff_tests_pl`) compares the interpreter with the translated code on them; all six agree and have every predicate attached natively.

## CI

The macOS job runs all six programs with the `N` of each line of `bench.json` and writes a table of the new times, the new ratio and the committed ratio to the Job Summary. It compares ratios (interpreter time divided by translated time), not milliseconds: both sides of a ratio run on the same runner, so the runner's speed cancels out, while the GitHub macOS runner's absolute times differ from the machine above by 20–80%. When a program's ratio is 20% or more below its committed ratio, the step prints a `::warning::` annotation and marks the row. When a measured or committed ratio is missing or zero, it prints a `::warning::` that the comparison was skipped. The step has a 20-minute timeout and never fails the job; it is a coarse regression alarm, not a measurement.

## Interpreter limits seen while choosing N

The heap is 1<<20 words and there is no garbage collection before phase 7. A failure-driven loop gets back the heap of each iteration, but deterministic work inside one iteration and the depth of `loop/1` stay on the heap:

- `tak`: the usual `tak(18, 12, 6)` (63609 calls) runs out of heap in a single call, so the program uses `tak(17, 11, 6)` (16701 calls, result 7). One call already uses about half of the heap, so `main` runs `check` inside `\+ \+` to give its heap back before `bench(N)`.
- `loop/1` itself: each level of the recursion leaves a choice point, and what it uses stays on the heap while later iterations run; a bare `loop(N), fail` runs out of heap between N = 40000 and 45000. This bounds `deriv`, the cheapest iteration, to N = 30000.

## nrev

`bench/nrev.pl`: naive reverse of a 30-element list (`nrev/2` and `app/3`), repeated `N` times by failure-driven backtracking. One `nrev` of 30 elements is 496 logical inferences. The run checks first that the first solution equals the reversed list.

| Date | Machine / OS | Build | N | Interpreter (ms) | Translated (ms) | Ratio |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-10-29 | Apple M1 Max, macOS 27.2, Apple clang 21.0 | Release | 20000 | 3147 | 149 | 21.2 |
| 2026-10-30 | Apple M1 Max, macOS 27.2, Apple clang 21.0 | Release | 20000 | 3290 | 143 | 23.0 |

The first row used the code `mosac emit` produced as of phase 6 Task 6: the first-argument dispatch (`select_clauses` rule), native-to-native calls by callee number, and head unification that reads the frame arguments directly (ADR 0009) were already in place from Task 4.

## queens

`bench/queens.pl`: all 92 solutions of 8 queens, placing one queen per column and checking the diagonals against the queens already placed (`sel/3`, `attack/3`, `\+`). The check is that the first solution is the lexicographically first one, 1,5,8,6,3,7,2,4 by column (the list holds the last-placed queen first).

## zebra

`bench/zebra.pl`: the five-houses puzzle, solved by unifying `house/5` terms against a list with `mem/2`, `right_of/3` and `next_to/3`. The search runs to the end on every iteration although there is one solution. The check is the whole known solution (the Japanese keeps the zebra, the Norwegian drinks water).

## tak

`bench/tak.pl`: the Takeuchi function `tak(17, 11, 6)` (see above for the size): integer arithmetic, comparison, and deterministic recursion with a cut. The check is that the result is 7.

## deriv

`bench/deriv.pl`: Warren's symbolic differentiation of four expressions per iteration (`ops8`, `divide10`, `log10`, `times10`), building and dropping terms. The check compares the derivative of `ops8` and of `x * x * x` with the terms worked out by hand.

## crypt

`bench/crypt.pl`: the multiplication puzzle OEE × EE = OOEE with partial products EOEE and EOE (E even, O odd digits), searched in full with digit lists (least significant first) and integer arithmetic. The check is the unique solution 348 × 28 = 9744 with partial products 2784 and 696.
