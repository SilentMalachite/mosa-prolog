## 背景

約 30000 段に入れ子した項を書くと C++ のスタックがあふれ、50000 要素のリストの原文を読むと `mosa` が落ちる（既定のスタックが 1 MiB の Windows では 20000 要素）。
入れ子の段ごと、またはリストの要素ごとに再帰する関数は、writer の `render` 一族（`render`、`render_op`、`render_list`、`render_functor`、`count`）、`Build::data`、`materialize`、`unify_cells`、そして `IrTerm` の暗黙の破棄と複製である。
2026-10-30 の所有者の決定 (2) で、writer はフェーズ7で繰り返しにする。SPEC 第6節は実行に C++ の再帰を使わない（トランポリン）と定め、ADR 0010 は writer を書き直すまでの間だけ portray の周りに `GcInhibit` を置いている。

## 決定

上の関数と同じ形の歩き手（copy_term の `export_rec`、findall の `encode`/`copy_cell`、`compare_seen`、`collect_vars`、clause/2 の `remember_slot`/`expose`、`acyclic_term`、`term_equal` の `match`、答えの `note_shown`）は、仕事を C++ のスタックでなく `std::vector` に手で積む。`IrTerm` には繰り返しで動く破棄、複製のコンストラクタ、複製の代入を持たせる（ムーブは既定のまま）。フィールドは変えない（ADR 0003）。
writer は文字列を返さず、出力へ順に書き足す。空白（`glue`）は、最後に書いた文字と次の字句の最初の文字を比べて決める。portray の `GcInhibit` は外し、writer の積んだ仕事、`open_`、`counts_`、`assigned_` を `RootScope`（ADR 0010）で知らせる。番地を鍵にする表は GC の後で作り直す。
目標: 実行時に作った項は深さ 1,000,000 まで（`f(f(...))`、リスト、`a+b+...` の左入れ子、`(a,b,...)` の右入れ子）、ソースのリストは 200,000 要素まで、どちらも 1 MiB のスタックで扱う。出力は、被演算子の演算子アトムの 7.10.5 の直しを除き、今と 1 バイトも変えない。`mosatest --bench` はインタプリタも翻訳も 5% 以内にする。

## 捨てた案

大きなスタックのスレッドで動かす案。限界を動かすだけで、組み込む側のプログラムや `mosac` の実行ファイルは呼ぶ側のスレッドを選べない。
深さに上限を設けてエラーにする案。ISO の項に深さの上限は無い。
reader も繰り返しにする案。ソースで 1 万段の入れ子（`f(f(...))`、`[[...]]`、`(...)`、xfy の右の被演算子の連鎖）はまれで、平らなリストと yfx の左の連鎖はもう繰り返しで読める。`Build::goal` の制御構造も、reader が先に限界に当たるので再帰のまま残す。

## 影響

`docs/iso-notes.md`（英日）の「7.1 項の入れ子の深さ」を、reader の入れ子だけの限界に書き直す。`mosac_long_list` は全 OS で 20000 要素で動く。
承認のとき、ADR 0010 の portray の例外の文（英日）を、この ADR で例外を外したと改める。
この ADR が承認されるまで、これに基づくコードは書かない。

## 改訂（2026-10-31、2026-10-31 承認）

背景: すべてを手で積むスタックにすると、インタプリタが 30〜80% 遅くなった（bench、phase7-iterative の Task 6）。また 1 MiB の下で測った reader の上限は `f(f(...))` で約 600 段で、上で想定した 1 万段ではなかった。
決定: よく通る歩き手（`IrTerm` の複製と破棄、`materialize`、`unify_cells`、`compare_seen`）は、深さを引数で渡して深さ 64 まで C++ の再帰で辿り、それより深い部分木だけを手で積むスタックへ移す。辿る順と割り当ての順は変えない。`term = std::move(term.args[1])` が正しく動くよう、`IrTerm` のムーブ代入は手で書く。制御構造の extra は、`launch` の間は写さずに取り出して戻す。同期の throw がそれを捨てたときは書き戻さない（`extras_low`）。
退けた案: スレッドローカルの深さの数（その費用が bench に出た）と、段ごとの extra の写し。結果: reader は再帰のまま残る。測った上限は iso-notes 7.1 にある。

## 改訂 2（2026-10-31、2026-10-31 承認）

背景: 上の退けた案は、reader がソースの入れ子を制限するとして `Build::goal` を再帰のまま残した。しかし実行時に組み立てたゴールは reader を通らない。長さ 100,000 の連言を `call/1` や `assertz/1` に渡すと、また深さ 100,000 の `E` で `X is E` を実行すると、8 MiB のスタックで SIGSEGV になる（2026-10-31 の main のレビュー）。算術の評価（`eval_expr`、`eval_args`）は上の一覧から漏れていた。
決定: `Build::goal`、`body_callable`、database の `goal_form`、`launch` の `IrTag::And` の左の被演算子、`eval_expr`/`eval_args` を最初の改訂と同じ形にする（深さ 64 まで C++ の再帰、それより深い部分木は手で積むスタック）。辿る順は変えず、最初に投げる誤りも変えない（引数より外側の関数子が先、引数は左から右）。IR は変えない（ADR 0003）。目標: 左にも右にも入れ子の、深さ 1,000,000 の連言と式を 1 MiB のスタックで扱う。`tests/stack/deep_builtins.pl` で確かめ、`mosatest --bench` は 5% 以内。
退けた案: 連言を n 引数の IR の節点に平らにする案（ADR 0003 を変える）。深さの上限で `resource_error` にする案（ISO は項の深さに上限を置かない）。結果: `mosac` のコード生成（`emit_body`、`check`）は入力が reader から来るので再帰のまま残す。iso-notes 7.1 に、実行時に組み立てたゴールと式には深さの上限がないことを 1 文足す。

## 改訂 3（2026-10-31、提案）

背景: ゴールを動かすと、その下位のゴールを写す。`embody` は連言の残りと `env` 全体を `Extra` ごとに写し、`;`、`->`、`*->`、`catch/3` は枝と `env` を `Entry` か `Extra` に写す。そのため、長さ n の右に入れ子の連言と選言は、時間もメモリも O(n²) かかる（`call/1` で `;` 2 万段に 41 秒。節の本体も同じ経路を通る）。また `launch` は、どの制御構造でも第 1 引数を C++ の再帰で降りる。そのため、1 MiB のスタックで `->` の条件や `catch/3` のゴールを 10 万段入れ子にすると SIGSEGV になる（左に入れ子の `;` が通るのは、コンパイラがその呼び出しを跳躍に変えたからにすぎない）。
決定: ゴールの木は写さずに共有する。`Clause::body` と `Compiled::term` を `std::shared_ptr<const IrTerm>` にし、`Extra::goal`/`then` と `Entry::else_goal`/`recovery` はその木の中を指す別名のポインタを持つ。`env` は共有するベクタにし、GC は 1 回の回収で 1 度だけ印を付けて書き換える。`launch_control` はポインタだけを写すので、`BorrowedExtra` と `extras_low`（改訂 1）は除く。`launch` は繰り返しにする。各制御構造は枠を積んだあと `launch` を呼ばず、最初の下位ゴールを返す。目標: 左にも右にも入れ子の、長さ 1,000,000 の `,` `;` `->` `*->` `catch/3` を、`call/1` と `assertz/1` を通して 1 MiB のスタックで、長さに比例する時間で扱う（`tests/stack/deep_builtins.pl`）。`mosatest --bench` は 5% 以内。
退けた案: 動かすときにゴールを `Extra` から取り出す案（継続はバックトラックのあとにもう一度動きうるので、ゴールは残す必要がある）。`IrTerm` の中に参照の数やアリーナを持たせる案（IR を変える。ADR 0003）。深さの上限（ISO 7.1 は上限を置かない）。結果: IR は変えない。`Clause::body` を読む所（`clause/2`、`listing/1`、指紋、`mosac` のコード生成）はポインタを辿る。iso-notes 7.1 から右に入れ子の連言の 2 万段の制限を除く。
