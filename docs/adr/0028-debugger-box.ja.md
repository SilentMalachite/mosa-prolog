状態: 承認済み（2026-11-18、持ち主。持ち主がフェーズ 14 の計画を頼んだことを承認とみなし、同じ日に持ち主は計画の実装を頼んだ）。SPEC 第 9 節はフェーズ 14（デバッガ）を定める。この ADR は、エンジンが呼び出しのポートを捕まえる形と、箱を作る者と、`abort` が実行を止める形を決める。

## 背景

トランポリンのエンジンはゴールを `step` の 1 か所で読むが、成功、再試行、失敗を捕まえる場所が無い。継続は `Goal` の中だけには無い。節に入る所と節のやり直し、非決定的な組込のやり直しは、継続をゴール枠の語 3 から読み直す。
だから `Goal` の `cont` を差し替えても出口の枠へ抜けない。`catch/3` は、選択点と出口の枠で、ゴールの出口と巻き戻しをすでに捕まえている（ADR 0012）。
ポートの行とコマンドには `mosa` のセッションにしか無い入出力が要り、`mosatest`、`mosac build` の実行ファイル、埋め込みの `Machine` は答えも出力も変えてはならない。

## 決定

`step` が見せるゴールを読み、セッションが機械に `DebugConsole` を渡しているときだけ、番兵 `Pick::DebugBox`、出口の枠 `Ctrl::DebugExit`、語 3 をその枠にしたゴール枠の写しを積み、写しを同じ歩みの中で動かす（`run_boxed`）。`Impl` は安全点をまたいでヒープの番地を持たない。成功は `DebugExit`（中に選択点が残るときは再試行用の `Pick::DebugRedo` も積む）で、失敗はバックトラックが番兵に着いたときに、例外は `propagate_throw` が、まだ抜けていない番兵を外すときに捕まえる（抜けた番兵と `Pick::DebugRedo` は黙って外す）。
`r` と `f` は番兵より上を `trim_stack` で切ってあとはバックトラックに任せ、後始末は ADR 0016 のとおりに動く。`nodebug/0` と `n` は leap に戻す。制御構文、`call/1..8`、デバッガの 9 つの述語、`$` の名前、ライブラリのモジュールからの呼び出しは箱を持たず、leap ではスパイポイントの述語だけが持つ。
`abort` は新しい止まり方 `StopKind::Abort` で、`halt` と同じ形にし、`run_loop` が `halt_now` の直後に見る。読み込みの中では、読み込みの誤りと同じにその読み込みを元に戻す。

## 却下した案

トレースするゴールのメタインタプリタ: 同じ節が 2 通りに動き、カット、後始末、誤りが食い違いうる。SPEC 第 1 節の目標 5（同じ結果）に反する。
節をポートのゴールを呼ぶ形に書き換える: データベースが変わり（`clause/2`）、デバッグを切っても負担が残る。
`Goal` の `cont` だけを差し替える: 語 3 を読み直す道では `DebugExit` に着かない。

## 結果

デバッグが切り、または `DebugConsole` が無いとき `step` の負担は分岐 1 つで、leap ではスパイポイントの呼び出しにだけ箱を作るので、スパイポイントまでは普段に近い速さで走る（持ち主の問い 2、決定 A。ベンチは 1.2 倍以内を守る）。
トレース中は末尾呼び出しでも箱が残り、深い再帰は深さに比例してメモリを使う。深さと `g` は開いている箱だけを数え、指令の中ではその中で開いた箱だけを数える。
