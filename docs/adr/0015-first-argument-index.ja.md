## 背景

呼び出しは第1引数を全部の節と比べ、生きている節を全部候補に並べる。retract と clause/2 は全部の節と単一化し、asserta は節のベクタと開いた走査を全部ずらし、節を消すたびにベクタから消して開いた走査の番号を全部付け直す。そのため N 節ではどれも 1 回 O(N) かかる（2026-10-31 のレビュー M3。鍵での retract 20,000 回 12.9 秒、asserta 40,000 回 5.6 秒、`p(_,_), !` 20,000 回 1.1 秒）。
バックトラックと節のやり直しは、そのたびに先頭の `Entry` を候補の列ごと写すので、N 節の 1 回の走査が O(N^2) になる。

## 決定

節は節の順に deque に置く。各節は変わらず使い回さない番号（asserta は先頭より小さく、assertz は末尾より大きく取る）と、足された世代と消された世代を持つ。走査は自分の世代で生きていた節だけを見る（7.5.4 の論理的更新ビュー）。第1引数が未束縛の走査はカーソル（次の番号と世代）を持ち、束縛された走査は候補の番号を並べる。8 節以上の述語では、候補を第1引数の索引（アトム、整数、浮動小数点数（-0.0 = 0.0、NaN = NaN）、リスト、名前/引数の数と、鍵の無い節）から取り、asserta と assertz が索引を延ばす。retract、retractall、clause/2 も同じ索引を使う。
消した節は、先頭か末尾にあり、その述語の開いた走査のどれもがまだそれに届かなければ（削除より古く、まだその節を過ぎていない走査が無ければ）すぐ消す。そうでなければ、列に残った死んだ節が節の数の半分を超えたときに 1 回の掃除で消す（掃除が開いた走査のために残した節は、それに届く一番下の走査が無くなってから再び数える。それまでは後で消した節だけを数えるので、長く開いた走査が変更のたびの掃除を起こさない）。番号は変わらないので、付け直しは無い。バックトラックとやり直しは先頭の `Entry` をその場で読む。

## 退けた案

候補を位置のまま持ち（ADR 0004/0008）、asserta と削除のたびに付け直す。asserta と途中の削除は O(N) のままで、未束縛の呼び出しも全部の節を並べ続ける。
変わらない番号を持たない世代番号、または節の連結リスト。前者は asserta で位置がずれ続け、後者は `enter_clause`、mosac、生成関数の指紋が使う添字での参照を失う。

## 影響

束縛された第1引数での呼び出し、retract、clause/2 は鍵の組と鍵の無い節の分だけかかり、未束縛の呼び出しと asserta は償却 O(1)、N 節の走査は線形になる。やり直しは番号で節を探す（先頭の節から探す節までの番号が続いている間は O(1)、そうでなければその位置より前を二分探索する。番号は使い回さないので、途中の掃除のあとだけでなく、先頭の節を消してから asserta したとき、末尾の節を消してから assertz したときにも欠番ができる）。
`dead` は「消された世代を持つ」になり、`held_by_scan` は世代と番号での確認になり、`note_asserta` と `note_removed` の節の部分は無くなり、`live_count` は数を持つだけになる。索引は節の頭部から取った鍵だけを持ち、ヒープのセルを持たないので、GC はこれを見ない。`std::deque` は述語ごとにブロック 1 つの費用がかかる。libc++ では最初の節のために 4 KB（`sizeof(Clause)` は 152 で、1 ブロックに 26 節）なので、節を 1 つずつ持つ 40,000 の述語は main の vector の 31 MB に対して 201 MB に達する（レビュー M21）。libstdc++ では約 0.5 KB、MSVC は `Clause` を 1 つずつブロックに割り当てるので、そこでは節ごとに割り当てが 1 回かかる。残した点（レビュー M3）: `loop :- retract(todo(X)), work(X), loop. loop.` は 2 乗のまま（1 周ごとに基の節の選択点が残るので、削除のたびに周の数だけ開いた走査を調べる。40,000 で約 3.7 秒、main も同じ）。残りの一致がすべて他に消された retract の走査は、最後の答えを確定として返し、あとで失敗する選択点を残さない（答えは同じ）。束縛した第1引数は呼び出しごとに組の全体の列を作り、古い開いた走査がまだ届く消えた先頭の節は、その後の呼び出しや retract が毎回位置 0 からまた歩いた（レビュー M20。下の改訂で直した）。後に直した（レビュー M19）: 入れ子の実行（開いた走査の中の consult の指令や初期化のゴール）に預けられた走査も開いた走査として数えるので、まだ届く消された節は残る。読み直しも置き換える節を消さず、同じく消された世代を付ける。静的な述語は assert も retract もされないので、走査が閉じた後の最初の呼び出しがそれを掃除する。
テスト: `index_scale`（節を 4 倍にしても、走査、asserta、未束縛の最初の呼び出し、鍵での引き当て、鍵での retract・retractall・clause/2、retract の走査、clause/2 の走査、カットのある場合とない場合の先頭からの retract、鍵での更新の時間が、それぞれ 8 倍に 30 ms を足した値未満）、`clause_scan_test`、`tests/pl/database.pl` の `m3_*`。

## 改訂（2026-11-04、レビュー M20。所有者の M20 の修正の依頼により承認）

背景: 第1引数を束縛した呼び出し、retract、clause/2 は、最初の答えの前に組の全体を並べていた（retract と clause/2 はその全部の節と単一化もした）。そのため 1 つの鍵の 20,000 節に対する `q(k,_), !` 20,000 回は 2.53 秒、10,000 節での `drain :- retract(q(k,_)), !, drain.` は 7.99 秒かかった。また、古い開いた走査がまだ届く消えた先頭の節は残るので、外側に `p(_)` があると、その後の未束縛の呼び出しや retract が毎回位置 0 からそれを 1 つずつ歩いた（40,000 節を空にするのに 0.89 秒。外側の走査が無ければ 0.10 秒）。
決定: 節の走査（呼び出し、retract、clause/2、retractall の歩み）はどれも、カーソル（次の番号と世代）と選ぶ鍵を持つ（第1引数が未束縛なら `Any`、鍵の型でない値に束縛されていれば鍵の無い節だけを取る `None`）。一歩では、カーソル以上の次の候補を、節の列から、または 8 節以上なら組と鍵の無い節の列から番号の二分探索で探し、次の候補があるときだけ選択点を残す（retract と clause/2 は、未束縛の走査がすでにそうしていたように、先にその頭部を試す）。やり直しは、前の一歩が `Entry::next` に残した組の位置の番号がまだカーソルならそこから始め、違えば二分探索する。歩みは走査を始めた後に生まれた最初の節で止まる。歩むのは走査がすでに見た節以上の番号だけで、asserta はどの番号よりも小さい番号を、assertz は一緒に増える番号と世代を与えるので、その先の節もみな新しい（敵対的レビュー A1）。上の決定の「候補の番号を並べる」の文はもう当てはまらない。死んだ節は飛び越しの幅を 2 つ持つ（節の列での `skip_all` と、同じ鍵の節（鍵の無い節は 1 つの鍵と数える）の中での `skip_key`。それぞれ 32 ビットで、あふれたら最大値に留め、死んだときは 1）。その番号の範囲の節は全部死んでいる。死んだ節を 1 つも見ない歩み（retract か、世代が述語の `last_death` 以上の走査）はこれに沿って跳び、跳んだ元の節をすべて跳んだ先に向け直す（経路圧縮）。節は生き返らない。失敗した consult が戻す写しの節は、写した時の番号、世代、幅を持ち、`next_id` は縮まないので、後で足す節が戻した幅の中に入ることもない。そのため assert、消去、掃除、戻しの後も幅は正しいまま（敵対的レビュー A5）。
退けた案: 節の列の死んだ先頭の後ろに印を 1 つだけ置く（レビューの案）。死んだ並びの前に asserta した節や、ある鍵の死んだ節が別の鍵の生きた節の間に並ぶ場合は、また 1 節ずつ歩く。番号の代わりに組の中の位置を持つ。asserta と先頭の消去で組の位置がずれ、掃除は索引を捨てる。
影響: k 個の答えで止まる呼び出しは、B 節の組で O(k + log B) と、1 つずつ踏み越える節の分で済み、鍵の選択点は列を持たない（1 つの組の `f(a,_)` の選択点を状態の上限で止めることはもう無い。`current_predicate/1` は今も列を持ち、数える）。`Clause` は 8 バイト増えて libc++ で 160 バイト（4 KB の deque のブロックに 25 節、レビュー M21）、`Entry` は `by_cursor` を失い 16 バイトの鍵を持つ（264 バイト）。残した点: 頭部が歩む節の 1 つにしか合わない retract と clause/2 は、選択点を残すかを決めるためにその残りを試す（M3 の決定性）ので、N 節の 1 つの鍵での `retract(q(k, 5))` と N 節での `retract(q(_, 5))` は前と同じく O(N) のまま（敵対的レビュー A4）。走査を始めた後にその述語の節が消されると、呼び出しと clause/2 の走査は見えない死んだ節を前と同じく 1 つずつ歩く。テスト: `index_scale`（最初の答えで止まる鍵での呼び出し、retract、clause/2 と、死んだ先頭の上の古い開いた走査の 2 つの再現の鍵あり・鍵なし、後で多くの節を assertz してからやり直す開いた走査）、`clause_scan_test`（鍵での決定性と、鍵で開いた走査の下でほかの鍵の死んだ節を捨てる掃除）、`tests/pl/database.pl` の `m20_*`。

## 改訂 2（2026-11-04、レビュー M21。所有者の M21 の修正の依頼により承認）

背景: `std::deque` は最初の要素で固定の塊を取る（libc++ で 4 KB、160 バイトの節 25 個。libstdc++ で 512 バイト。MSVC は節ごとに 1 回の確保と表）。そのため libc++ では、1 節の述語 4 万個が consult で 211 MB、assertz で 210 MB を使った。M3 より前の vector では 31 MB だった（レビュー M21）。代わりにどの列も 1 本の vector にすると、伸びる間は古い配列と新しい配列を両方持つ。1 述語の 16 万節は最大 113 MB になり、deque の 49 MB を上回った（macOS、この改訂の最初の版で測った）。
決定: `ClauseList`（`src/machine/clause_list.hpp`）は `kVectorLimit`（16）節までを `std::vector<Clause>` に置く。vector は自分の大きさの半分ずつ伸び、上限を超えない。節が上限を超えるときに `std::deque<Clause>` へ移す（`std::unique_ptr` の先に置き、その時に初めて作る。先に空の節で長さを取ってから noexcept の移動代入で埋めるので、`bad_alloc` でも節を失わない）。消して deque の節が 8 以下になるか、vector が半分未満しか使われず余りが 4 つ以上になれば、節だけの大きさの vector へ移す。vector での asserta と真ん中の削除が動かすのは 16 節までなので、両端は均して O(1)、添字は O(1) のままである。32 でなく 16 にするのは、32 では 17〜32 節の asserta と先頭の retract が最大 19% 遅くなり、libc++ の deque の塊はどのみち 25 節を持つからである（敵対的レビュー B1）。反復子は列と位置を持つので、列が今の場所にある間だけ使える（deque の反復子は述語表の移動の後も使えた。`add_predicate` をまたいで反復子を持つ所は無い）。写しは節だけを持つ。節は列を変えると場所が変わり、列の変更をまたいで `Clause&` を持つ所は無い（走査は番号で持ち、`enter_clause`、retract、clause/2、`kill_clause` は列を変える前に節を読み終える）。
退けた案: どの列も前に空きを持つ 1 本の vector にする（上の伸長の山）。小さい塊の deque（標準では塊の大きさを選べない）。自前の塊の列（同じメモリのために 2 つ目の deque を保守することになる）。`std::unique_ptr<Clause>` の vector（節ごとに確保が 1 回、節を読むたびにポインタが 1 段増える）。`boost::container::devector`（新しい依存）。
影響: libc++ で `Predicate` は 304 から 288 バイトに、`Snapshot` は 128 から 112 に減り、列の移動は deque の移動が noexcept かに頼らなくなる。16 節を超える述語の費用は、どの OS でも deque のときと同じである。9〜16 節の述語の先頭で asserta と retract だけを繰り返すループは、deque より最大 9% 遅い。メモリと速さの値は [bench.md](../bench.ja.md) の「小さな節の vector の費用」にある。テスト: `clause_list_test`（1 節の列が持つ場所は 1 つ、deque への移動と戻り、両端、待ち行列、縮め、反復子、写し）と、asserta、先頭の削除、走査が線形のままかを確かめる `index_scale`。
