## 背景

フェーズ4で SPEC 第5節のモジュール系を足す。今の述語は (名前, アリティ) だけで引かれ、ゴールフレームはどのモジュールで動くかを持たない。
`Module:Goal`、`meta_predicate/1` の引数、限定のない `assertz/1` は、実行時に文脈モジュールが要る。
フェーズ6の `mosac` も同じゴールフレームを生成する（ADR 0003）ので、コードより先に形を決める。

## 決定

Predicate にモジュール（モジュール名の原子番号）を持たせ、鍵を (モジュール, 名前, アリティ) にする。`system` は C++ の組み込みと制御構文を持ち、`user` は既定のモジュールである。
ゴールフレーム（0 語目が 0 でない）の 1 語目は、ビット 0〜15 がアリティ、ビット 16〜47 が文脈モジュールの原子番号である。kFrameHead は 4 のままで、IR は変えない。本体のゴールは、その節の述語のモジュールを受け継ぐ。切り替えるのは `M:G` と `meta_predicate/1` の引数だけである。
引く順は `system` が先（`system` の名前を定義すると `permission_error(modify, static_procedure, PI)`）、次に文脈モジュールの定義と取り込み、最後にその既定の取り込み元である。演算子はモジュール固有、`user`、ISO の核の順に引く。公開リストの `op/3` は取り込み側の固有層に入る。

## 捨てた案

すべてのゴールフレームに 5 語目を足す案。アリティの語に収まる値のために、全フレームが 1 語太る。
節を読み込むときに述語を解決し、その番号をフレームに入れる案。後から定義した述語や assert した述語が見えない。
演算子の表を全体で 1 つにする案。SPEC 第5節は `op/3` を宣言したモジュールに閉じると決めている。

## 影響

制御フレーム（0 語目が 0）の 1 語目は、今どおり extras の添字である。ゴールフレームの 1 語目の読み書きは、すべて `read_goal` と `write_goal` を通す。
フェーズ6の `mosac` は同じビットに文脈モジュールを書く。フェーズ7の GC はこの語を項として走査しない。
Reader と Writer は OperatorTable ではなく演算子の見え方を受け取る。この ADR が承認されるまで、モジュールのコードは書かない。
