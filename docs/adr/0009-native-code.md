## Context

The owner chose coexistence A (2026-10-29): the executable embeds the source and loads it with today's loader, and only static predicates whose IR matches what `mosac` translated switch to C++ functions on the trampoline (ADR 0003 frames, ADR 0006 goal word, ADR 0008 dead marks stay).
A throwaway spike (macOS, Release, one process, median of 5) ran 30-element `nrev` 20000 times in a failure-driven loop: the interpreter took 3352 ms and hand-written `nrev/2` and `app/3` following this ADR, with the unit lookup of `regs` searching 4 units, took 150 ms, 22.3 times faster (a first spike with executable-wide numbers took 130 ms against 3271 ms).
The same functions with every clause variable created fresh and every head argument passed to `rt::unify` took 1125 ms (3.0 times), and 2.1 times (first spike, median of 3) when `rt::unify` was plain `do_unify`: the remaining cost is head unification (the vectors of `do_unify`'s `Attempt`), so heads are specialised below.

## Decision

After `load_source` of an embedded unit's source returns (the program's units before the `initialization(_, main)` goals, a library unit when `use_module/1` loads it), each `NativeEntry` whose `(module, name, arity, fingerprint)` matches a static predicate is attached as `Predicate::native` and in the matching `calls` entries of every unit. Any later write to that predicate's clauses or `meta` (a `consult/1` that defines it again, a multifile addition, a rolled-back load) calls `detach_native`, which clears all of them at once, and nothing re-attaches it. The predicate stays an ordinary static `Predicate` with its IR clauses, so `assertz/1`, `retract/1`, `clause/2`, `abolish/1` and `predicate_property/2` behave as now and throw `permission_error(modify, static_procedure, PI)`. `clause_fingerprint` is a 64-bit FNV-1a over the `meta_predicate/1` arguments and then the clauses' IR in order (tag, slot, arity, integer, float bits, and each atom as its UTF-8 name with its length, never its number); the translator and the loader call the same function.
`NativeProc` is `void (*)(Machine::Impl& machine, std::uint64_t frame, std::uint32_t state)`. `state` 0 is the call, which chooses clauses by the first argument with the rule of `select_clauses`; `state_of(clause, point) = clause << 16 | point` with clauses counted from 1, where point 0 enters that clause's head on redo and point n ≥ 1 is the clause's n-th resume point, numbered in the order the translator creates them (the continuation after a call, or the branch, then, else, done, recovery and exit points of a nested control construct; Task 7), not "after body goal n". The cut barrier is `regs.cut` (`Impl::native_cut`, which the runtime sets before every call and redo) in state 0 and clause-entry states, and word 2 of the `Ctrl::Native` frame in a resume state (a recovery state takes `choice_mark` at entry instead, 7.8.9). A resume point continues from a `Ctrl::Native` frame on the heap with no `extras` entry: word 0 = 0, word 1 = bit 63 | count of the cells from word 5 << 32 | state, word 2 = cut barrier, word 3 = continuation, word 4 = the `NativeProc`, words 5 and on = first that state's `skip` control words (small-int cells holding a choice-stack height, a soft-cut id or a catch index, which the state's prologue consumes), then the clause's live variable cells. Alternatives push `Pick::Native` (`redo_goal` = a frame, `candidates` = the remaining states, `cut` = the barrier): `push_alternative` uses the goal frame and `Entry::native` = the proc, while `push_branch` and `push_soft` use a resume frame and read the proc and the state from its words 4 and 1; redo calls the proc with `candidates[next]`. `push_catch` pushes `Pick::Catch` with `redo_goal` = the recovery resume frame, and `propagate_throw` sets `ip` to that frame instead of launching an IR recovery goal.
Each translation unit holds one `constinit rt::UnitTag`; `regs(machine, tag)` finds that unit's per-Machine tables by the tag's address once per activation, and callee and atom numbers are local to the unit (`NativeUnit::calls` and `atoms`). `call_goal(machine, regs, number, args, cont, cut)` writes the ordinary goal frame and, if callee `number` is attached in that very module, sets `Impl::native_next`, which the next `step` runs before `run_builtin` and which `backtrack` and `propagate_throw` clear; otherwise the frame goes to `run_builtin` and `enter_user` unchanged. Until Tasks 6 and 7, generated code raises no errors itself and every built-in goes through `call_goal`. `runtime.hpp` sees `Machine::Impl` as an opaque type and inlines `Cell::tag`, `Heap::data()` and `rt::` free functions that read cells and write terms (`put_*`); only `install_unit`, `regs`, `alloc`, `bind`, `unify`, `call_goal`, `resume_frame`, `push_alternative`, `cut_to`, `proceed`, `fail` and `interpret_clause` are out of line, with the exact declarations in plan Task 3 **Interfaces** (Task 7 adds the out-of-line control-construct, catch, qualify and arithmetic entry points declared in `runtime.hpp`). Head unification is emitted per argument (deref, switch on the tag, match or build, `bind`) and calls `unify` only for a repeated variable or a non-variable subterm against a bound cell.

## Rejected alternatives

Keeping `Ctrl::Native` in `extras` like the other control frames, since `step_control` copies the `Extra` with its vector on every continuation; marking the callee's frame itself as a control frame, since it would lose the name and module word (ADR 0006) that errors and the interpreter fallback read.
The SPEC section 6 form `bool pred_X_N(Machine& m, Cell* args, Cont k)`, since ADR 0003's goal frame already holds the arguments and the continuation and a resume needs a state (the frame stands for `args` and `k`, and failure is `machine.failed`); calling the callee's C++ function from the caller, since the C++ stack would grow with the Prolog depth (Review Focus 4); numbering callees by their position in `Impl::predicates`, since `abolish/1` erases from that vector and shifts the positions.
Executable-wide callee and atom numbers, since plan Task 10 ships prebuilt per-library units compiled before any program exists; head unification through `do_unify` for every argument (2.1 times in the spike); moving `Heap::deref` and the other `Heap` members inline in `heap.hpp`, since that speeds up the interpreter too and moves the denominator of the ratio (plan Task 6).

## Consequences

ADR 0003 gains a third frame kind: a control frame whose word 1 has bit 63 set is `Ctrl::Native`, and ADR 0006's "word 1 is the extras index" holds only when bit 63 is clear. The phase 7 GC marks words 5 and on of that frame as cells (the control words are small-int cells, so the rule holds) and does not read word 4 as a term.
Task 3 writes the declarations in plan Task 3 **Interfaces**, which replace that plan's earlier list (`fresh`, `make_*`, `bind_atom`, `bind_int`), and adds only `Predicate::native`, `Pick::Native`, `Ctrl::Native`, `Entry::native`, `Impl::native_units`, `native_next` and `native_cut`. Generated code creates the clause variables it leaves unbound in slot order and binds in the direction of `enter_clause` (the clause side is the left operand of `do_unify`), which Task 4's `native_var_order` fixes.
On approval, SPEC section 6 (English and Japanese) is updated to this function form and cut barrier. Resolving an embedded unit's `include/1`, `ensure_loaded/1` and `library(_)` without a file search is left to Tasks 5 and 10 (Review Focus 5). No code is written on this ADR before it is approved.
