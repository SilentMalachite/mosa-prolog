Status: Proposed (2026-10-29)

## Context

The owner chose coexistence A (2026-10-29): the executable embeds the source and loads it with today's loader, and only static predicates whose IR matches what `mosac` translated switch to C++ functions on the trampoline (ADR 0003 frames, ADR 0006 goal word, ADR 0008 dead marks stay).
A throwaway spike (macOS, Release, one process, median of 5) ran 30-element `nrev` 20000 times in a failure-driven loop: the interpreter took 3271 ms and hand-written `nrev/2` and `app/3` following this ADR took 130 ms, 25.2 times faster (the `build/` interpreter took 3.19 s from the command line).
The same functions with every clause variable created fresh and every head argument passed to `rt::unify` took 1069 ms (3.1 times), and 1571 ms (2.1 times, median of 3) when `rt::unify` was plain `do_unify`: the remaining cost is head unification (the vectors of `do_unify`'s `Attempt`), so heads are specialised below.

## Decision

When loading the embedded source has defined a static predicate, a `NativeEntry` whose `(module, name, arity, fingerprint)` all match is attached as `Predicate::native` and in every `Impl::native_calls` entry with that key; a later `consult/1` that defines it again detaches both. The fingerprint is `clause_fingerprint`, a 64-bit FNV-1a over the clauses' IR in order (tag, slot, arity, integer, float bits, and each atom as its UTF-8 name with its length, never its number), and the translator and the loader call the same function.
`using NativeProc = void (*)(Machine::Impl& machine, std::uint64_t frame, std::uint32_t state);`. `state` 0 is the call, which chooses clauses by the first argument with the rule of `select_clauses`; `state_of(clause, goal) = clause << 16 | goal` with clauses counted from 1, where goal 0 enters that clause's head on redo and goal g resumes after body goal g. The cut barrier is `Impl::native_cut` (read as `regs.cut`), which the runtime sets before every call and redo; a resume state reads it from word 2 of its `Ctrl::Native` frame instead. A body goal after the first resumes from a `Ctrl::Native` frame on the heap, with no `extras` entry: word 0 = 0, word 1 = bit 63 | variable count << 32 | state, word 2 = cut barrier, word 3 = continuation, word 4 = the `NativeProc`, words 5 and on = the clause's variable cells. Alternatives push `Pick::Native` (`Entry::native` = the proc, `redo_goal` = the goal frame, `candidates` = the remaining states, `cut` = the barrier), and redo calls the same proc with `candidates[next]`.
Generated code calls with `rt::call_goal(machine, number, args, cont, cut)`, where `number` indexes `Impl::native_calls`, the executable-wide callee table that `mosac` numbers: it writes the ordinary goal frame, and if that callee (module, name, arity) is an attached predicate of that very module it sets `Impl::native_next`, which `step` runs before `run_builtin`; otherwise the frame goes to `run_builtin` and `enter_user` unchanged. `runtime.hpp` sees `Machine::Impl` as an opaque type and inlines `Cell::tag` (cell.hpp), `Heap::data()` (heap.hpp) and `rt::` free functions for deref, unbound, tag tests, list and structure reads, atom and small-integer cells, frame argument and variable reads, and writing terms into allocated words. Only these are out of line: `regs` (heap words, atom table, cut barrier; once per activation), `alloc` (one block per clause), `bind` (conditional trail), `unify` (variable and identical-cell fast path, then `do_unify`), `call_goal`, `resume_frame`, `push_alternative`, `cut_to`, `proceed`, `fail`, `interpret_clause`. Head unification is emitted per argument (deref, switch on the tag, match or build, `bind`) and calls `unify` only for a repeated variable or a non-variable subterm against a bound cell.

## Rejected alternatives

Keeping `Ctrl::Native` in `extras` like the other control frames, since `step_control` copies the `Extra` with its vector on every continuation; marking the callee's frame itself as a control frame, since it would lose the name and module word (ADR 0006) that errors and the interpreter fallback read.
The SPEC section 6 form `bool pred_X_N(Machine& m, Cell* args, Cont k)`, since ADR 0003's goal frame already holds the arguments and the continuation and a resume needs a state (the frame stands for `args` and `k`, and failure is `machine.failed`); calling the callee's C++ function from the caller, since the C++ stack would grow with the Prolog depth (Review Focus 4); numbering callees by their position in `Impl::predicates`, since `abolish/1` erases from that vector and shifts the positions.
Head unification through `do_unify` for every argument (2.1 times in the spike); moving `Heap::deref` and the other `Heap` members inline in `heap.hpp`, since that speeds up the interpreter too and moves the denominator of the ratio (plan Task 6).

## Consequences

ADR 0003 gains a third frame kind: a control frame whose word 1 has bit 63 set is `Ctrl::Native`, and ADR 0006's "word 1 is the extras index" holds only when bit 63 is clear. The phase 7 GC marks words 5 and on of that frame as cells and does not read word 4 as a term.
`NativeUnit` gains `calls`, the executable-wide callee keys (index = `number`), next to `atoms`, which is executable-wide as well (generated code reads atom i as `regs.atoms[i]`); `interpret_clause(machine, number, frame, clause)` runs that clause from its IR. Task 3 writes the signatures above, and `Predicate::native`, `Pick::Native`, `Ctrl::Native`, `Entry::native` and `Impl::native_calls`, `native_atoms`, `native_next`, `native_cut` are the only machine members it adds.
Generated code creates the clause variables that it leaves unbound in slot order and binds in the direction of `enter_clause` (the clause side is the left operand of `do_unify`), which Task 4's `native_var_order` fixes. No code is written on this ADR before it is approved.
