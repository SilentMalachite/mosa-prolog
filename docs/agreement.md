# Interpreter / translated agreement

This file is generated by `mosatest --diff`. Do not edit by hand.

Each test file is loaded twice from the same bytes: as IR by the interpreter, and as C++ emitted by `mosac emit --units` and attached with `install_unit`. Both sides run the same `'$mosa_diff_goal'(K, Vars)` queries, and the answers, error terms and standard output are compared byte by byte. "Compared" counts the compared lines (one per goal, plus one load line per `.pl` file; `.lgt` files add their failure and summary lines). ## How answers are compared

Each answer is one term `'$a'(V1, ..., Vn)` over all query variables in goal order, written without the query names: unnamed variables are `_G<n>` by first occurrence inside that one write, so sharing between bindings (`f(A), g(A)` vs `f(A), g(B)`) and aliasing of unbound variables (`X = Y`) stay visible, while the identity of the cells does not matter. `mosa`'s toplevel text itself differs for 11 goals, because native head unification binds the clause variables straight to the query cells and the IR goes through fresh cells (the writer prints a query variable's name for its own cell): control.pl cyclic_not, cyclic_once, cyclic_call_var, cyclic_findall, cyclic_forall, cyclic_catch_goal, cyclic_not_not_eq; lib_lists.pl length_cyclic, sort_cyclic, msort_cyclic; native.pl native_var_head (`L = [a,b|L]` vs `L = [a,b|_]`, `T = t(X,W,Y)` vs `T = t(_G1,_G2,_G1)`). As substitutions they agree, and the table above counts them as agreeing. For `solutions([...])` tests one more solution than expected is asked for on both sides.

The term is written in canonical form (functional notation, lists in brackets, atoms and numbers quoted as `writeq/1` does, a re-entered open structure as `_`) by an iterative walk rather than by `write_term/2`: the writer recurses once per nesting level, and the answer of tests/pl/types.pl `ground_deep` (`f/1` nested 30000 deep) overflows an 8 MB stack. CTest raises the stack limit of its children, which hides the overflow there, but a run from a shell or on Windows would not survive it.

## Goals not given the clause shape

Goals that cannot take the shape `'$mosa_diff_goal'(K, Vars) :- Goal.` run as plain queries on both sides and count as not translated.

| Directory | Shape | Count |
| --- | --- | ---: |
| tests/conformance | judge | 832 |

- `judge`: the expected outcome is not one of true/false/error/assertion (deterministic, variant, subsumes, ball, exists, all), or the body uses Logtalk-only calls; the Logtalk runner judges these with its own machinery on both sides, so the goal text is not rewritten (the file's own predicates still run natively on the translated side).
- `unsupported`: an outcome kind the Logtalk runner does not handle.
- `unreadable`: the assembled goal text does not read back as one term.
