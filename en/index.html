Write rules, even in Japanese, and ask Prolog for answers

Mosa Prolog is a system that runs programs written in the Prolog language. In Prolog you do not write steps; you write what is true. Write down facts and rules, ask a question, and Mosa follows the rules to find the answers. Names can be in Japanese, so rules written in Japanese read as plain Japanese.

Download the latest release Read the manual

This page describes 0.3.0, released on 16 November 2026; see the release notes for what changed. It runs on macOS, Linux and Windows, under the Apache-2.0 license.

Prolog searches for the answer when you ask

Most programs are a list of steps: do this, then do that. In Prolog you write what is true (facts) and what follows from it (rules). Then you ask a question, and Prolog takes care of how to search for the answer.

If a query holds, the answer is true. If Mosa finds no way to make it hold, the answer is false. It never makes up a plausible answer when there is none.

A name that starts with an upper-case letter or an underscore, like X, is a variable. Put a variable in a query and Mosa shows the values that make it true. When there is more than one answer, each ; you type shows the next one.

Prolog suits work like this:

  • the rules behind a decision can be written down
  • a mistake is costly, and you must be able to explain why a result came out
  • the job is to search many combinations for the ones that fit

If the work is mostly totalling large amounts of data, SQL and similar tools fit better.

Asking about a fact
?- 親(太郎, 花子).
true.
?- 親(花子, 太郎).
false.
Asking with a variable
?- 親(太郎, X).
X = 一郎;

X = 花子.
?- 親(X, 三郎).
X = 次郎.

Three commands

They are in the bin folder of the package. To start with, mosa is all you need.

mosa

Run Prolog interactively

Type queries at the ?- prompt, or load and run files. Nothing else needs to be installed.

$ mosa 家族.pl

mosac

Build an executable

Translates a Prolog program to C++, compiles it, and produces one file that runs on computers without Mosa.

$ mosac build app.pl -o app

mosatest

Run tests

Runs tests written in Prolog. With --diff, it checks that mosa and mosac give the same answers.

$ mosatest tests/pl/

Write it in Japanese

Mosa reads and writes UTF-8. Atoms (names of things, like 東京), predicates (names of relations, like 親) and variables can all be Japanese, and errors and warnings can be in Japanese too.

Variables start with an underscore

Japanese has no upper and lower case, so 太郎 is an atom. A variable with a Japanese name starts with an underscore, as in _太郎.

?- 名前 = 太郎.
false.
?- _名前 = 太郎.
_名前 = 太郎.
家系.pl
親(太郎, 一郎).
親(一郎, 花子).
祖父母(_祖, _孫) :- 親(_祖, _親), 親(_親, _孫).
$ mosa 家系.pl -g "祖父母(X, 花子)." -t halt
X = 太郎.

One character counts as one

Mosa counts each Unicode character as one. Even 𠮷, which lies outside the Basic Multilingual Plane, is a single character.

?- atom_length(東京, N).
N = 2.
?- atom_length('𠮷野家', N).
N = 3.
?- atom_chars(日本語, L).
L = [日,本,語].

Full-width punctuation works too

With a Japanese input method switched on, you type （, 、 and 。 instead of (, , and .. Mosa normally rejects them, but with the flag japanese_punctuation set to true it reads them as their ASCII counterparts. The corner brackets 「」 act as single quotes.

?- X = 親（子）。
Syntax error: line 1 column 6: unexpected token （
?- set_prolog_flag(japanese_punctuation, true).
true.
?- X = 親（太郎、一郎）。
X = 親(太郎,一郎).
?- X = 「東 京」。
X = '東 京'.

Files in full-width punctuation

A directive on the first line turns the mode on until the end of the file. That one line is written in ASCII.

capital.pl
:- set_prolog_flag(japanese_punctuation, true).

capital（日本、東京）。
capital（フランス、パリ）。
capital（アメリカ、「ワシントン D.C.」）。
?- consult('capital.pl').
true.
?- capital(X, Y).
X = 日本, Y = 東京;

X = フランス, Y = パリ;

X = アメリカ, Y = 'ワシントン D.C.'.

Messages are in Japanese when the LANG environment variable starts with ja, and in English otherwise. The flag message_language switches them too. Chapter 11 of the manual has the details.

Turn a program into one executable you can hand over

mosac translates a Prolog program to C++ and calls a compiler to build an executable. The result runs on a computer with no Mosa, no Prolog files and no compiler, so a set of rules can be shipped as a small tool that makes decisions.

A C++ compiler is needed only when you build with mosac: Xcode Command Line Tools on macOS, g++ on Linux, and Build Tools for Visual Studio 2022 on Windows.

As a rough guide to speed, on seven benchmark programs the executables ran 1.0 to 26.6 times as fast as the interpreter (Apple M1 Max, measured in November 2026; see the benchmark record).

hello.pl
:- initialization(main, main).

main :- write(hello), nl.
$ mosac build hello.pl -o hello
$ ./hello
hello

The first line, initialization(main, main), tells Mosa to run main after loading the file and then exit. Chapter 13 of the manual walks through it.

How closely it follows the standard, in published numbers

Prolog has an international standard, ISO/IEC 13211-1. Mosa is built to follow it, and the results of the tests that measure how closely it does are public. The tests run on macOS, Linux and Windows CI on every change.

Design decisions that are hard to change later are written down as architecture decision records (ADRs) before they are implemented; there are 26 as of 0.3.0. What Mosa cannot do yet is listed under known limitations in the CHANGELOG.

Let an LLM draft the rules, and let people check them

LLMs are good with language, but they do not always give the same answer to the same question, and their reasons are hard to trace. Prolog runs written rules the same way every time and answers false when the rules do not support a claim. The two can share the work.

  1. An LLM drafts the rulesIt turns rules written in prose into Prolog facts and rules.
  2. People read the rules and correct themWhen the rules are written in Japanese, experts in the field can read them as they are.
  3. Mosa decides by the rulesThe same input gives the same answer. Built with mosac, the rules ship as a standalone checker.
A rule that checks a record of excavated layers
直接上位(a層, b層).
直接上位(b層, c層).

より上(A, B) :- 直接上位(A, B).
より上(A, B) :- 直接上位(A, C), より上(C, B).

矛盾 :- より上(X, X).  % 自分より上にある層があれば記録の矛盾

直接上位 means directly above, より上 above, and 矛盾 contradiction. The comment says that if a layer lies above itself, the record contradicts itself.

Prolog can promise only that it answers by the rules as written. If a rule is wrong, so is the answer. That is why the rules are kept in a form people can read.

The author’s article Prologは死んだのか？ ― LLM時代における論理プログラミングの現在地 (in Japanese) discusses this in depth.

From download to your first query

Unpack the prebuilt package and make it callable from your shell. mosa needs nothing else installed.

macOS
macOS 26 or later (Apple Silicon)
Linux
x86_64, with glibc the same as Ubuntu 24.04 or newer
Windows
Windows 10 22H2 or later, and Windows 11 (x64), with Smart App Control turned off
Note
The packages are not signed. Chapter 2 of the manual explains what to do when the OS blocks them.

  1. Download the package

    Download the package for your computer. Each file name below is a direct download of the 0.3.0 package, and the commands that follow are for 0.3.0 too. If a newer release is out, get it from the Releases page and change the version number to match.

    ComputerPackage
    macOS (Apple Silicon)mosa-0.3.0-macos-arm64.tar.gz
    Linux (x86_64)mosa-0.3.0-linux-x86_64.tar.gz
    Windows (x64)mosa-0.3.0-windows-x86_64.zip

  2. Unpack it in your home folder

    The commands assume the package is in your Downloads folder.

    macOS (Terminal)
    Terminal
    $ cd ~
$ tar -xzf ~/Downloads/mosa-0.3.0-macos-arm64.tar.gz
    Linux (terminal)
    Terminal
    $ cd ~
$ tar -xzf ~/Downloads/mosa-0.3.0-linux-x86_64.tar.gz
    Windows (PowerShell)
    PowerShell
    Expand-Archive "$HOME\Downloads\mosa-0.3.0-windows-x86_64.zip" -DestinationPath $HOME

  3. Remove the quarantine mark (macOS only)

    macOS marks files downloaded with a web browser as quarantined, and does not open unsigned programs that carry the mark. This command removes it from the folder and every file in it.

    Terminal
    $ xattr -dr com.apple.quarantine ~/mosa-0.3.0-macos-arm64

  4. Add the bin folder to PATH

    PATH is the list of folders your shell searches when you type a command name. The change takes effect in windows you open afterwards.

    macOS (zsh)
    Terminal (zsh)
    $ echo 'export PATH="$HOME/mosa-0.3.0-macos-arm64/bin:$PATH"' >> ~/.zshrc
    Linux (bash)
    Terminal (bash)
    $ echo 'export PATH="$HOME/mosa-0.3.0-linux-x86_64/bin:$PATH"' >> ~/.bashrc
    Windows (PowerShell)
    PowerShell (type one line at a time)
    $bin = "$HOME\mosa-0.3.0-windows-x86_64\bin"
$old = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$old;$bin", "User")

  5. Check that your shell finds Mosa

    Open a new window and type mosa --version. If it prints the version, you are ready.

    Shell
    $ mosa --version
mosa 0.3.0

  6. Make your first query

    Type mosa to get the ?- prompt. Type one query at a time and press Enter. Every query ends with a period, and halt. quits.

    $ mosa
?- X = こんにちは.
X = こんにちは.
?- atom_length(こんにちは, N).
N = 5.
?- halt.

    Typing Japanese in a Windows console window has not been tested yet (see the known limitations in the CHANGELOG). If it does not work, write the Japanese text in a file and load that.

If something goes wrong, see chapter 2 of the manual, Getting and starting Mosa. It covers macOS refusing to open the program, the blue protection screen on Windows, and a shell that cannot find mosa.
